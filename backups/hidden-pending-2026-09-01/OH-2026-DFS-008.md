## 漏洞概述

`SoftbusSession::Start`、`Stop`、`SendData` 和 `SendFile` 使用 `sessionMutex_` 访问 `sessionId_`，但 `GetSessionId` 直接无锁返回该字段。会话释放与 SoftBus 关闭回调可以并发执行，因此 getter 能与 `Stop` 的写入重叠。

## 根本原因

**位置**：`services/cloudsyncservice/include/transport/softbus/softbus_session.h`

```cpp
int32_t GetSessionId() const
{
    return sessionId_; // 未持有 sessionMutex_
}
```

`SessionManager::RemoveSendSession` 在自身的 vector 锁下调用 getter，但 `ReleaseSession` 会在 vector 锁外调用 `Stop`。两把锁不保护同一个会话字段。

## 影响

- 会话可能未从缓存移除或被重复关闭。
- 后续发送可能使用旧 session ID 并失败。
- 无锁读写构成 C++ 数据竞争。

## 触发条件

本地释放会话的同时，SoftBus 触发 `OnSessionClosed` 回调并进入会话缓存清理路径。

## 修复建议

让 `GetSessionId` 使用 `sessionMutex_`，或将 session ID 改为具有明确状态转换规则的原子值。避免用管理器容器锁替代会话对象自己的状态锁。
