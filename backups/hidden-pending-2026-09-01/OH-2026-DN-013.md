## 漏洞概述

通知订阅记录的添加和删除主要依赖 `notificationSubQueue_` 串行执行，部分修改还使用 `subscriberRecordListMutex_`。`GetSubscriberRecords` 却从另一条服务路径直接按值复制 `subscriberRecordList_`，既没有获取互斥锁，也没有进入相同队列。

## 根本原因

**位置**：`services/ans/src/notification_subscriber_manager.cpp`

```cpp
std::list<sptr<NotificationRecord>> GetSubscriberRecords() const
{
    return subscriberRecordList_; // 绕过 mutex 和 notificationSubQueue_
}
```

`AdvancedNotificationService::RecoverLiveViewForUser` 会从账户恢复路径调用 getter。账户恢复与队列中的订阅插入或删除可以并发。

## 影响

- 在 `std::list` 修改期间复制容器会产生数据竞争和未定义行为。
- Live View 恢复可能得到缺失、重复或不一致的订阅记录。
- 极端交错下可能造成通知服务稳定性异常。

## 触发条件

系统账户恢复或服务启动执行 `RecoverLiveViewForUser` 时，系统应用或 native subsystem 正在增加或删除通知订阅者。

## 修复建议

让 `GetSubscriberRecords` 使用 `subscriberRecordListMutex_` 返回一致快照，或把获取快照的操作提交到 `notificationSubQueue_`，确保与所有修改路径使用同一序列化规则。
