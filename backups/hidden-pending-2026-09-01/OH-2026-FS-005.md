## 漏洞概述

`BundleFileUtils::RemoveFile` 先调用 `IsExistFile()` 检查文件存在性，再调用 `remove()` 删除。检查与删除之间存在竞争窗口，攻击者可在窗口内通过符号链接替换使 `remove()` 删除非预期文件。

## 根本原因

**位置**: `services/bundlemgr_lite/src/bundle_file_utils.cpp:107`

```cpp
bool BundleFileUtils::RemoveFile(const char *path)
{
    if (IsExistFile(path)) {       // CHECK: 文件存在
        return remove(path) == 0;  // USE: 删除 — 竞争窗口
    }
    return true;
}
```

**问题**:
1. `IsExistFile()` 与 `remove()` 之间存在竞争窗口
2. 攻击者可将 `path` 替换为符号链接
3. `remove()` 跟随符号链接删除目标文件
4. 在 bundle 卸载/清理流程中频繁调用

## 影响

- 可删除非预期文件
- 在 bundle 卸载流程中可能删除其他应用的数据
- 系统配置文件被删除可导致服务异常

## 触发条件

1. 攻击者对目标路径所在目录有写权限
2. BMS 执行 bundle 卸载或清理操作调用 `RemoveFile`
3. 在 `IsExistFile()` 返回 true 之后、`remove()` 执行之前
4. 攻击者将目标路径替换为指向关键文件的符号链接
5. `remove()` 删除符号链接指向的文件

## 修复建议

```cpp
bool BundleFileUtils::RemoveFile(const char *path)
{
-   if (IsExistFile(path)) {
-       return remove(path) == 0;
-   }
-   return true;
+   // 直接尝试删除，通过返回值判断
+   if (remove(path) == 0) {
+       return true;
+   }
+   // ENOENT 表示文件不存在，视为成功
+   return (errno == ENOENT);
}
```
