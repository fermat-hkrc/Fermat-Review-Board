## 漏洞概述

`SpanString` 的 TLV 解码器在读取定长数值和带长度字段的数据时，没有验证游标及声明长度是否位于输入缓冲区内。截断或伪造的 TLV 数据可使解码器构造超出 `std::vector<uint8_t>` 边界的迭代器，并从无效范围复制数据。

外部数据存在两条实际入口：`StyledString.unmarshalling` 接受调用方提供的任意 `ArrayBuffer`，剪贴板读取流程也会把 `openharmony.styled-string` 自定义数据直接交给 `SpanString::DecodeTlv`。在目标应用处理恶意数据时，该缺陷可造成越界读取、未定义行为和进程崩溃。

受影响版本仅确认当前 `master` 提交 `d8847980b8c1fdbb6e79b5a9b641cabde4ba9a70`。尚未确认首个受影响发行版或已修复发行版。

## 根本原因

### 定长数值读取未检查剩余字节数

**位置**: `frameworks/core/components_ng/pattern/text/span/tlv_util.cpp:71`

```cpp
double TLVUtil::ReadDouble(std::vector<uint8_t>& buff, int32_t& cursor)
{
    if (ReadUint8(buff, cursor) != TLV_DOUBLE_TAG) {
        return 0.0;
    }
    auto start = buff.begin() + cursor;
    auto end = start + sizeof(double);
    double value;
    std::copy(start, end, reinterpret_cast<uint8_t*>(&value));
    cursor += sizeof(double);
    return value;
}
```

函数只验证类型标签，没有检查标签后是否还剩 `sizeof(double)` 个字节。输入在标签后截断时，`end` 超出容器边界，随后 `std::copy` 从无效范围读取。`ReadFloat` 在同一文件第 93 行使用相同模式；`ReadDimension`、`ReadTextShadow` 和 `ReadCalcLength` 均可间接进入 `ReadDouble`。

### 声明长度未与输入缓冲区核对

**位置**: `frameworks/core/components_ng/pattern/text/span/tlv_util.cpp:327`

```cpp
auto pixelMapLength = ReadInt32(buff, cursor);
if (pixelMapLength == 0) {
    return nullptr;
}
std::vector<uint8_t> pixelMapSubVec(
    buff.begin() + cursor, buff.begin() + cursor + pixelMapLength);
cursor += pixelMapLength;
```

`ReadPixelMap` 只排除长度为零的情况。负数长度以及大于剩余缓冲区的长度都会生成无效迭代器范围。

**位置**: `frameworks/core/components_ng/pattern/text/span/span_string.cpp:1248`

```cpp
auto buffLength = TLVUtil::ReadInt32(buff, cursor);
if (buffLength == 0) {
    continue;
}
auto lastCursor = cursor;
// ...
auto endOfUserDataArrBuff = buffLength + cursor + cursor - lastCursor;
std::vector<uint8_t> bufferSubVec(
    buff.begin() + cursor, buff.begin() + endOfUserDataArrBuff);
// ...
cursor = lastCursor + buffLength;
```

`DecodeTlvExt` 同样没有拒绝负数长度，也没有验证计算出的结束位置及更新后的游标是否超过 `buff.size()`。因此，定长字段、PixelMap 数据和扩展 Span 数据都依赖输入声明，而不是实际剩余字节数。

## 影响

- 在目标应用进程中触发越界读取和 C++ 未定义行为。
- 造成剪贴板读取或 `StyledString.unmarshalling` 异常终止，形成拒绝服务。
- `ReadPixelMap` 和扩展 Span 路径还可能因无效迭代器范围触发异常分配或崩溃。

尚未执行真机或内存检测器测试，因此当前不声称稳定的信息泄露、内存写入或代码执行。

## 触发条件

1. 调用方将恶意 TLV 字节放入 `StyledString.unmarshalling` 的 `ArrayBuffer`；或者能够写入剪贴板的数据源提供仅包含 `openharmony.styled-string` 自定义数据的记录。
2. TLV 数据选择包含 `double`、`float`、Dimension、TextShadow、CalcLength、PixelMap 或扩展 Span 的字段。
3. 定长字段在有效载荷结束前被截断，或长度字段为负数、超过剩余缓冲区长度。
4. 目标应用调用解码接口或读取对应剪贴板记录，解码器使用未校验的游标或长度构造迭代器。

## 修复建议

在所有读取操作前使用统一的剩余长度检查，并以减法比较避免 `cursor + length` 整数溢出。解析失败时应立即停止整个 TLV 解码过程，而不是返回与合法数据无法区分的默认值。

```cpp
static bool HasRemaining(const std::vector<uint8_t>& buff, int32_t cursor, size_t length)
{
    if (cursor < 0) {
        return false;
    }
    const auto offset = static_cast<size_t>(cursor);
    return offset <= buff.size() && length <= buff.size() - offset;
}

double TLVUtil::ReadDouble(std::vector<uint8_t>& buff, int32_t& cursor)
{
    if (ReadUint8(buff, cursor) != TLV_DOUBLE_TAG ||
        !HasRemaining(buff, cursor, sizeof(double))) {
        return 0.0;
    }
    double value;
    std::copy_n(buff.begin() + cursor, sizeof(double),
        reinterpret_cast<uint8_t*>(&value));
    cursor += sizeof(double);
    return value;
}
```

对声明长度应先拒绝非正值，再转换为无符号类型并检查剩余空间：

```cpp
if (pixelMapLength <= 0 ||
    !HasRemaining(buff, cursor, static_cast<size_t>(pixelMapLength))) {
    return nullptr;
}
```

`ReadFloat`、`ReadPixelMap` 和 `DecodeTlvExt` 应采用相同检查。建议同时增加截断 `double`/`float`、负数长度、长度等于剩余字节数、长度超过剩余字节数以及入口级 `ArrayBuffer` 和剪贴板数据回归测试。
