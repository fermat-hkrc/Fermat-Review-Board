## 漏洞概述

`GetSensorInfos()` 分别从 IPC reply 中读取 `notify->count` 和 `len`，但未验证 `len >= count * sizeof(SensorInfo)`。攻击者可设置 count 为较大值但 len 为较小值，导致 `ReadBuffer` 返回的缓冲区实际大小远小于循环访问的范围，在 memcpy_s 的源地址侧发生堆越界读取。

## 问题代码

**文件**: `frameworks/src/sensor_agent_proxy.c`

```c
// Line 139-156
ReadInt32(reply, &(notify->count));       // ← 例如 count = 10
uint32_t len = 0;
ReadUint32(reply, &len);                  // ← 例如 len = sizeof(SensorInfo) * 1
uint8_t *data = (uint8_t *)ReadBuffer(reply, (size_t)len);
// data 指向仅 1 个 SensorInfo 大小的缓冲区

if ((notify->count <= 0) || (data == NULL)) {
    // ⚠️ 未检查 len 与 count 的一致性
    ...
}
SensorInfo *sensorInfo = (SensorInfo *)(data);
*(notify->sensorInfo) = (SensorInfo *)malloc(sizeof(SensorInfo) * notify->count);

for (int32_t i = 0; i < notify->count; i++) {
    memcpy_s((*(notify->sensorInfo) + i), sizeof(SensorInfo),
        (sensorInfo + i),    // ← 当 i >= 1 时，读取超出 data 缓冲区
        sizeof(SensorInfo));
}
```

## 触发条件

1. 攻击者控制 Sensor Service 的 IPC 响应
2. 设置 `count = N`（如 10），`len = sizeof(SensorInfo) * 1`
3. `ReadBuffer` 返回仅包含 1 个 SensorInfo 的缓冲区
4. 循环从第 2 次迭代开始读取越界内存

## 影响

- 堆越界读取（信息泄露，可读取相邻堆块内容）
- 泄露的数据通过 `notify->sensorInfo` 返回给调用者
- 进程崩溃（读取未映射内存时 SIGSEGV）

## PoC 验证

```bash
gcc -fsanitize=address -fno-omit-frame-pointer -g -O0 poc.c -o /tmp/poc && /tmp/poc
```

ASan 输出：
```
ERROR: AddressSanitizer: heap-buffer-overflow on address 0x50f0000000e4
READ of size ... at 0x50f0000000e4 thread T0
```

## 修复建议

```c
ReadInt32(reply, &(notify->count));
uint32_t len = 0;
ReadUint32(reply, &len);
uint8_t *data = (uint8_t *)ReadBuffer(reply, (size_t)len);
- if ((notify->count <= 0) || (data == NULL)) {
+ if ((notify->count <= 0) || (data == NULL) ||
+     (len < (uint32_t)(notify->count * sizeof(SensorInfo)))) {
      notify->retCode = SENSOR_ERROR_INVALID_PARAM;
      return SENSOR_ERROR_INVALID_PARAM;
  }
```
