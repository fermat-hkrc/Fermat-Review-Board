## 漏洞概述

异步读取完成路径在 `readLock` 下写 `CloudDiskFile::type`，但 `FileOperationsCloud::Read` 和 `Release` 无锁读取该字段并据此选择本地 FD 或云端 session 处理路径。同一 FUSE handle 的读取、释放和异步完成任务可以在不同线程重叠。

## 根本原因

**位置**：`services/cloudfiledaemon/src/cloud_disk/file_operations_cloud.cpp`

```cpp
{
    std::lock_guard lock(filePtr->readLock);
    filePtr->type = CLOUD_DISK_FILE_TYPE_CLOUD;
}

if (filePtr->type == CLOUD_DISK_FILE_TYPE_LOCAL) { // 无锁读取
    return ReadLocal(filePtr);
}
```

写入方使用的 `readLock` 没有覆盖消费方。局部 `shared_ptr` 能保护对象生命周期，但不能消除普通字段的数据竞争。

## 影响

- 读取路径可能依据不一致的类型状态选择错误处理分支。
- 可表现为读请求失败、释放逻辑异常或暂时错误状态。
- 当前完成回调通常重复写入 cloud 类型，因此实际影响较低，但 C++ 数据竞争仍然存在。

## 触发条件

同一 Cloud Disk handle 的 `Read` 或 `Release` 与异步 `HandleReadCompletion` 回调并发执行。

## 修复建议

所有 `type` 读写使用 `readLock`，或将类型改为满足状态机要求的原子变量。选择 FD/session 路径时应在锁内取得一次一致快照。
