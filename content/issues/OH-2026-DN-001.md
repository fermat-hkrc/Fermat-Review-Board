## 漏洞概述

`NotificationPreferencesDatabase::GetDistributedEnabledForBundle` 通过引用参数 `enabled` 返回分布式通知或实况窗开关状态。函数进入后先把 `enabled` 作为 `%{public}d` 字段写入 DEBUG 日志，之后才为它设置默认值或读取数据库。

当前生产代码中存在直接触发该缺陷的调用点：同文件的三参数重载声明未初始化的 `int32_t notification` 和 `int32_t liveView`，再将其传给上述函数。该重载由本地分布式应用列表和通知数据克隆流程调用，不是测试或示例代码。

在没有自动变量初始化保护的构建中，日志参数求值会读取不确定的栈值，属于 C++ 未定义行为；当 DEBUG 日志实际输出时，该 32 位数值还会以公共字段而非隐私字段记录。OpenHarmony 标准系统的 OHOS C++ target 默认对普通局部变量进行零初始化，因此标准构建中的直接信息泄露风险会明显降低，但日志记录的仍不是查询结果，源码也依赖编译器加固掩盖了错误的输出参数使用顺序。

当前 `master` 提交 `c76a751c286e4e3fc614b4fccd57dfbfa13d2aa3` 仍存在该问题。日志先于输出参数赋值的行为由提交 `bd6e1a64f8d9db24a848e2f7e4184a4645df27a3` 于 2024-02-29 引入；本地可核对的公开标签中，`OpenHarmony-v6.0-Release` 已包含相同顺序。当前两个未初始化 `int32_t` 调用点由提交 `9ba3d033b4a02a76397548cee236e75e28de6844` 于 2026-03-09 引入。尚未确认已修复发行版。

## 根本原因

### 输出参数在默认赋值前参与日志参数求值

**位置**: `services/ans/src/notification_preferences_database.cpp:3245`

```cpp
bool NotificationPreferencesDatabase::GetDistributedEnabledForBundle(const std::string deviceType,
    const bool isNotification, const NotificationPreferencesInfo::BundleInfo &bundleInfo, int32_t &enabled)
{
    ANS_LOGD("%{public}s, deviceType:%{public}s,enabled[%{public}d]", __FUNCTION__, deviceType.c_str(), enabled);
    if (bundleInfo.GetBundleName().empty()) {
        ANS_LOGE("Bundle name is null.");
        return false;
    }

    std::string key = GenerateBundleLablel(bundleInfo, deviceType);
    if (!isNotification) {
        key = GenerateLiveViewBundleLabel(bundleInfo, deviceType);
    }
    enabled = static_cast<int32_t>(NotificationConstant::SWITCH_STATE::USER_MODIFIED_OFF);
```

`enabled` 是只用于返回结果的输出参数。入口日志却在输入检查、默认值设置和数据库查询之前读取它。`ANS_LOGD` 最终调用 `HILOG_IMPL` 的 `LOG_DEBUG` 级别，而格式中的 `%{public}d` 明确要求按公共数字字段处理该值。

当包名为空时，函数甚至会在读取并记录 `enabled` 后直接返回，整个函数都不会为输出参数赋值。

### 生产调用点传入未初始化局部变量

**位置**: `services/ans/src/notification_preferences_database.cpp:1347`

```cpp
void NotificationPreferencesDatabase::GetDistributedEnabledForBundle(
    const NotificationPreferencesInfo::BundleInfo& bundleInfo,
    const std::string& deviceType, NotificationDistributedBundle& distributedBundle)
{
    int32_t notification;
    if (GetDistributedEnabledForBundle(deviceType, true, bundleInfo, notification)) {
        distributedBundle.SetNotificationEnable(static_cast<NotificationConstant::SWITCH_STATE>(notification));
    }

    int32_t liveView;
    if (GetDistributedEnabledForBundle(deviceType, false, bundleInfo, liveView)) {
        distributedBundle.SetLiveViewEnable(static_cast<NotificationConstant::SWITCH_STATE>(liveView));
    }
```

两个局部变量在声明时都没有初始化。四参数重载进入后首先记录它们，因此默认赋值并不能阻止此前发生的读取。

本地分布式列表路径为：`AdvancedNotificationService::GetLocalDistributedBundleList` → `NotificationPreferences::GetLocalDistributedBundles` → `ParseDistributedInfoFromDB` → 三参数重载 → 四参数重载。该服务入口仅在全场景协同功能启用时使用，并要求调用方具有 native token 和通知控制权限。通知数据备份路径也会通过 `GetAllCloneBundlesInfo` 和 `GetDistributedEnabledForClone` 进入同一三参数重载。

`services/ans/BUILD.gn` 将 `notification_preferences.cpp` 和 `notification_preferences_database.cpp` 编译进 `ans_service_sources`，`ans_service` 共享库依赖该 source set。组件构建配置默认启用全场景协同功能，因此上述实现和至少一条调用链进入产品服务构建。

## 影响

- DEBUG 日志可能记录与真实分布式开关状态无关的值，干扰故障定位和状态审计。
- 在未启用局部变量自动初始化的构建中，读取未初始化的 `int32_t` 属于 C++ 未定义行为；若日志被输出并可读取，公共数字字段可能暴露一个先前栈值。
- 标准 OpenHarmony C++ 构建默认将普通局部变量置零，且该 target 没有关闭这项保护。在这种配置下，直接栈值暴露通常会退化为记录误导性的零值，但这项编译器保护不能替代正确的源码初始化。
- 函数在日志之后会为合法请求设置默认值并查询数据库，因此当前没有证据表明返回的开关状态会稳定损坏。

本次没有执行设备日志采集或关闭自动变量初始化后的动态测试。当前证据不支持稳定的信息泄露、进程崩溃、权限提升或普通应用可直接读取该服务日志的结论。

## 触发条件

1. 系统内部执行通知数据克隆，或具有 native token 和通知控制权限的调用方请求本地分布式应用列表。
2. 代码进入三参数 `GetDistributedEnabledForBundle`，并把未初始化的 `notification` 或 `liveView` 传给四参数重载。
3. 四参数重载在设置默认值之前求值入口日志中的 `enabled`。
4. 若要形成可观察的栈值暴露，还需要目标构建未启用自动变量初始化、DEBUG 日志被实际输出，并且观察者有权读取相应日志。

普通应用不满足已核对服务入口的 native token 和通知控制权限要求。当前尚未发现绕过这些权限检查的路径。

## 修复建议

入口日志不应读取尚未写入的输出参数。最小修改是从入口日志删除 `enabled`，并在函数开始时为输出参数建立明确的默认值；如需记录查询结果，应在数据库查询结束后再输出最终值。

```cpp
bool NotificationPreferencesDatabase::GetDistributedEnabledForBundle(const std::string deviceType,
    const bool isNotification, const NotificationPreferencesInfo::BundleInfo &bundleInfo, int32_t &enabled)
{
    enabled = static_cast<int32_t>(NotificationConstant::SWITCH_STATE::USER_MODIFIED_OFF);
    if (deviceType == NotificationConstant::PAD_DEVICE_TYPE ||
        deviceType == NotificationConstant::PC_DEVICE_TYPE) {
        enabled = static_cast<int32_t>(NotificationConstant::SWITCH_STATE::SYSTEM_DEFAULT_ON);
    }
    ANS_LOGD("%{public}s, deviceType:%{public}s", __FUNCTION__, deviceType.c_str());

    if (bundleInfo.GetBundleName().empty()) {
        return false;
    }
    // 查询数据库；如需记录 enabled，应在查询完成后记录最终值。
```

三参数重载中的两个局部变量也应在声明时初始化，作为调用侧的防御性措施。服务接口的输出参数应统一遵循“函数返回前由被调用方赋值，调用方不需要预先提供有效值”的约定。
