## 漏洞概述

`BundleMsFeature::HandleGetBundleInfosByIndex` 从 IPC 请求中读取 `index` 值后直接用于数组访问，无任何边界检查。同时未校验 `GetInnerBundleInfos()` 的返回值是否为 nullptr。攻击者可通过发送恶意 IPC 请求使 BMS 系统服务崩溃（DoS）。

## 根本原因

**位置**: `services/bundlemgr_lite/src/bundle_ms_feature.cpp:615`

```cpp
uint8_t BundleMsFeature::HandleGetBundleInfosByIndex(const uint8_t funcId, IpcIo *req, IpcIo *reply)
{
    int32_t lengthOfBundleInfo = 0;
    BundleInfo *bundleInfos = GetInnerBundleInfos(req, reply, &lengthOfBundleInfo);
    // 无 null 检查 — GetInnerBundleInfos 在非法 codeFlag 时返回 nullptr

    int32_t index = 0;
    ReadInt32(req, &index);
    // 攻击者完全控制 index，无范围验证

    char *str = ConvertUtils::ConvertBundleInfoToString(bundleInfos + index);
    // 触发点：
    //   1. bundleInfos == nullptr → nullptr + offset → SIGSEGV
    //   2. index < 0 || index >= lengthOfBundleInfo → 堆越界读
    ...
}
```

**问题**:
1. `GetInnerBundleInfos()` 返回 nullptr 时无检查直接使用
2. `index` 来自 IPC 不可信输入，无边界校验
3. 同文件其他函数（如 `HandleGetBundleInfos`）有正确的 null 检查，此处遗漏

## 影响

- BMS 系统服务进程 SIGSEGV 崩溃（DoS）
- 后续所有 bundle 管理操作（安装/卸载/查询）不可用
- 堆越界读可能泄露堆上敏感数据（信息泄露）
- 任意 app 仅需基本 IPC 权限即可触发

## 触发条件

1. 攻击 app 通过 SAMGR 获取 BMS 服务的 IPC 客户端代理
2. 构造 `GET_BUNDLE_INFO_BY_INDEX` (funcId=10) 请求
3. 设置非法 codeFlag（如 99）使 `GetInnerBundleInfos` 返回 nullptr
4. 设置任意 index 值（如 0x41414141）
5. BMS 服务访问 `nullptr + index * sizeof(BundleInfo)` → SIGSEGV

## 修复建议

```cpp
uint8_t BundleMsFeature::HandleGetBundleInfosByIndex(const uint8_t funcId, IpcIo *req, IpcIo *reply)
{
    int32_t lengthOfBundleInfo = 0;
    BundleInfo *bundleInfos = GetInnerBundleInfos(req, reply, &lengthOfBundleInfo);
+   if (bundleInfos == nullptr || lengthOfBundleInfo <= 0) {
+       return ERR_APPEXECFWK_OBJECT_NULL;
+   }

    int32_t index = 0;
    ReadInt32(req, &index);
+   if (index < 0 || index >= lengthOfBundleInfo) {
+       BundleInfoUtils::FreeBundleInfos(bundleInfos, lengthOfBundleInfo);
+       return ERR_APPEXECFWK_QUERY_PARAMETER_ERROR;
+   }

    char *str = ConvertUtils::ConvertBundleInfoToString(bundleInfos + index);
    ...
}
```
