## 漏洞概述

camera sample 应用的 `app_manage.cpp` 中，将 `bundleName` 拷贝到固定大小的 `appName_` 缓冲区时使用 `strlen(bundleName)` 作为长度参数，未检查是否超出缓冲区大小。当 bundleName 长度 >= 128 字节时，后续的 null 终止写入越界。

## 根本原因

**位置**: `services/bundlemgr_lite/bundle_daemon/sample/app_manage.cpp:32`

```cpp
#define MAX_APP_NAME 128

struct AppInfo {
    char appName_[MAX_APP_NAME];
    // ...
};

void InitAppInfo(AppInfo *pApp, BundleInfo *pBundleInfo)
{
    memcpy_s(pApp->appName_, sizeof(pApp->appName_),
             pBundleInfo->bundleName, strlen(pBundleInfo->bundleName));
    pApp->appName_[strlen(pBundleInfo->bundleName)] = 0;
    // ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
    // 如果 strlen(bundleName) >= 128，写入位置超出 appName_[] 边界
}
```

**问题**:
1. `memcpy_s` 的目标大小参数限制了拷贝量，但不会报错
2. null 终止符写入使用原始 `strlen()` 值作为索引
3. 当 `strlen(bundleName) >= MAX_APP_NAME` 时，`appName_[128]` 越界写入
4. 覆写结构体中 `appName_` 之后的相邻字段

## 影响

- 栈/堆上相邻数据被 0x00 覆写
- 可能破坏结构体其他字段
- 程序行为异常或崩溃

## 触发条件

1. 安装 bundleName 长度 >= 128 字节的应用包
2. camera sample 调用 `GetAailityInfosByBundleName` 获取 bundle 信息
3. `InitAppInfo` 拷贝超长 bundleName
4. null 终止符写入越界位置

## 修复建议

```cpp
void InitAppInfo(AppInfo *pApp, BundleInfo *pBundleInfo)
{
    size_t nameLen = strlen(pBundleInfo->bundleName);
+   if (nameLen >= sizeof(pApp->appName_)) {
+       nameLen = sizeof(pApp->appName_) - 1;
+   }
-   memcpy_s(pApp->appName_, sizeof(pApp->appName_),
-            pBundleInfo->bundleName, strlen(pBundleInfo->bundleName));
-   pApp->appName_[strlen(pBundleInfo->bundleName)] = 0;
+   memcpy_s(pApp->appName_, sizeof(pApp->appName_),
+            pBundleInfo->bundleName, nameLen);
+   pApp->appName_[nameLen] = 0;
}
```
