## 漏洞概述

`DatabaseManager::GetRdbStore` 在 `mapLock_` 下检查并插入 `rdbMap_`，随后主动释放锁，再通过 `rdbMap_[key]` 执行第二次容器查找。该查找可以与其他 FUSE 线程的插入和 rehash 并发，导致共享 `cloudfiledaemon` 中的未定义行为。

## 根本原因

**位置**：`services/cloudfiledaemon/src/cloud_disk/database_manager.cpp:27`

```cpp
std::unique_lock lock(mapLock_);
if (rdbMap_.find(key) == rdbMap_.end()) {
    rdbMap_[key] = CreateRdbStore(key);
}
lock.unlock();
return rdbMap_[key]; // 解锁后再次遍历 unordered_map
```

FUSE 使用 `fuse_session_loop_mt`。不同应用并发首次访问各自 bundle 时，一个线程可以在无锁查找期间与另一个线程的插入和 rehash 重叠。

## 影响

- 解引用失效 bucket 或 node，导致 `cloudfiledaemon` 崩溃。
- 返回错误的数据库对象，引发文件操作失败或数据状态异常。
- daemon 服务多个应用，一个调用者触发的崩溃会影响其他 Cloud Disk 用户。

## 触发条件

两个应用并发对各自 Cloud Disk 目录执行首次数据库访问，使两个不同 key 的 `GetRdbStore` 调用重叠并触发 `unordered_map` 插入或 rehash。

## 修复建议

在持锁期间保存目标 `shared_ptr`，然后直接返回该局部副本。不得在释放 `mapLock_` 后再次访问 `rdbMap_`。
