## 漏洞概述

`BundleManager::DeserializeSystemCapabilities` 从 IPC 响应中读取 `sysCapCount` 后直接用于 `sizeof(SystemCapName) * sysCapCount` 的乘法运算作为 `AdapterMalloc` 参数。在 32 位 LiteOS-A 平台上，精心构造的 `sysCapCount` 值可使乘法溢出，分配一个远小于预期的缓冲区，后续循环写入造成堆溢出。

## 根本原因

**位置**: `services/bundlemgr_lite/src/bundle_manager.cpp:213`

```cpp
void BundleManager::DeserializeSystemCapabilities(IpcIo *reply, BundleInfo *info)
{
    int32_t sysCapCount;
    ReadInt32(reply, &sysCapCount);
    // sysCapCount 来自 IPC，攻击者完全控制

    info->systemCap.systemCapNum = sysCapCount;
    info->systemCap.systemCapName =
        (SystemCapName *)AdapterMalloc(sizeof(SystemCapName) * sysCapCount);
    // sizeof(SystemCapName) = 64
    // 在 32 位平台：64 * 0x04000001 = 0x100000040 → 截断为 0x40 (64 字节)
    // 实际只分配了 64 字节

    for (int32_t index = 0; index < sysCapCount; index++) {
        // 循环 0x04000001 次，每次写入 64 字节 → 堆溢出
        char *capName = (char *)ReadString(reply, &len);
        if (capName != NULL && len > 0) {
            memcpy_s(info->systemCap.systemCapName[index].name,
                     sizeof(info->systemCap.systemCapName[index].name),
                     capName, len);
        }
    }
}
```

**问题**:
1. `sysCapCount` 无上限检查
2. `sizeof(SystemCapName) * sysCapCount` 在 32 位平台可整数溢出
3. 循环以原始 `sysCapCount` 为边界执行，远超实际分配大小

## 影响

- 堆缓冲区溢出可覆写相邻堆元数据和对象
- 潜在任意代码执行（通过堆 metadata 腐败控制流）
- BMS 服务崩溃（DoS）
- 影响所有调用 `GetBundleInfo` 系列接口的路径

## 触发条件

1. 攻击者控制 BMS IPC 响应数据（中间人或恶意服务端场景）
2. 在 IPC 响应中设置 `sysCapCount = 0x04000001`
3. 客户端调用 `DeserializeSystemCapabilities` 解析响应
4. `AdapterMalloc(64 * 0x04000001)` 溢出为 `AdapterMalloc(64)`
5. 循环写入 64 * 67M 字节到 64 字节缓冲区 → 堆溢出

## 修复建议

```cpp
void BundleManager::DeserializeSystemCapabilities(IpcIo *reply, BundleInfo *info)
{
    int32_t sysCapCount;
    ReadInt32(reply, &sysCapCount);
+   if (sysCapCount <= 0 || sysCapCount > MAX_SYSCAP_NUM) {
+       return;
+   }
+
+   size_t allocSize = sizeof(SystemCapName) * (size_t)sysCapCount;
+   if (allocSize / sizeof(SystemCapName) != (size_t)sysCapCount) {
+       return;  // overflow check
+   }

    info->systemCap.systemCapNum = sysCapCount;
-   info->systemCap.systemCapName =
-       (SystemCapName *)AdapterMalloc(sizeof(SystemCapName) * sysCapCount);
+   info->systemCap.systemCapName = (SystemCapName *)AdapterMalloc(allocSize);
    ...
}
```
