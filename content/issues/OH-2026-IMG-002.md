## 漏洞概述

`PngNinePatchRes::DeviceToFile()` 使用 `numXDivs`、`numYDivs`、`numColors` 作为循环上界遍历 dividers/colors 数组，执行 `htonl()` 字节序转换。这些字段来自 `PngNinePatchRes` 结构体本身（由外部数据 Deserialize 而来），但函数不验证它们与实际分配的缓冲区大小是否一致。当字段值大于实际分配的数组元素数量时，触发堆越界读写。

该函数当前在生产代码中无调用者（死代码），但作为公共接口暴露在 `png_ninepatch_res.h` 中。

## 问题代码

**文件**: `plugins/common/libs/image/libpngplugin/src/png_ninepatch_res.cpp`

```cpp
// Line 44-62
void PngNinePatchRes::DeviceToFile()
{
    int32_t *xDivs = GetXDivs();
    for (int i = 0; i < numXDivs; i++) {
        xDivs[i] = htonl(xDivs[i]);  // ← 无边界检查，numXDivs 来自不可信数据
    }
    int32_t *yDivs = GetYDivs();
    for (int i = 0; i < numYDivs; i++) {
        yDivs[i] = htonl(yDivs[i]);  // ← 同上
    }
    // ...
    uint32_t *colors = GetColors();
    for (int i = 0; i < numColors; i++) {
        colors[i] = htonl(colors[i]);  // ← 同上
    }
}
```

`GetXDivs()` 返回 `(int32_t*)((uint8_t*)this + xDivsOffset)`，即结构体之后的内存。如果 `numXDivs` 大于该区域实际分配的 int32_t 数量，循环将越界读写。

**对比**: 同类函数 `FileToDevice()`（line 64-82）存在相同问题，但其唯一调用者 `ReadChunk` 通过 `length == SerializedSize()` 验证保证了缓冲区大小一致。`DeviceToFile()` 无此保护。

## 触发条件

1. 通过 `Deserialize()` 将外部数据 cast 为 `PngNinePatchRes*`（Deserialize 不验证 numXDivs 与缓冲区大小的关系）
2. 调用 `DeviceToFile()`
3. `numXDivs` 大于实际分配的 dividers 数量 → 越界读写

## 影响

- 堆越界读（读取 `xDivs[i]`）+ 堆越界写（写回 `htonl` 结果）
- 进程崩溃（DoS）
- 潜在的信息泄漏（越界读）和内存破坏（越界写）
- 代码维护风险：公共 API 无防御性检查，未来调用者可能不经过 ReadChunk 验证路径

## PoC 验证

**方法**: Target-Compile — 编译真实 `png_ninepatch_res.cpp` 为 `.o`，链接 ASan 插桩二进制，通过公共 API `Deserialize` → `DeviceToFile` 触发。

**触发路径**:

## 修复建议

方案一：为 `DeviceToFile` 添加 size 参数进行边界验证：

```diff
- void PngNinePatchRes::DeviceToFile()
+ void PngNinePatchRes::DeviceToFile(size_t bufferSize)
  {
+     size_t expectedSize = SerializedSize();
+     if (bufferSize < expectedSize) {
+         return;
+     }
      int32_t *xDivs = GetXDivs();
      for (int i = 0; i < numXDivs; i++) {
          xDivs[i] = htonl(xDivs[i]);
      }
```

方案二：如果确认该函数不再需要，直接移除死代码：

```diff
  // png_ninepatch_res.h
- void DeviceToFile();
  void FileToDevice();

  // png_ninepatch_res.cpp
- void PngNinePatchRes::DeviceToFile() { ... }
```
