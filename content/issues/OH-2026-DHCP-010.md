## 问题概述

DHCP 服务端发送 OFFER、ACK 或 NAK 报文时，`sendto` 返回 `-1` 的失败结果会被当作成功处理。上层随后记录发送成功并继续执行。

## 根本原因

两个发送路径均用 `!ret` 检查结果：

```cpp
int ret = sendto(...);
if (!ret) {
    return RET_FAILED;
}
return RET_SUCCESS;
```

`sendto` 在失败时返回 `-1`，而 `!-1` 为假；只有返回 `0` 才会进入失败分支。对于非空 DHCP 报文，成功时通常返回已发送字节数。

## 影响

- 实际未发出的 DHCP 回复会被服务端当作已发送。
- 上层无法获知发送异常，也不会按失败路径处理。
- 客户端可能超时后重试，服务端日志却显示回复已完成。

## 触发条件

1. 服务端进入 OFFER、ACK 或 NAK 回复发送路径。
2. 套接字在发送时返回 `-1`，例如文件描述符异常、网络接口异常或底层发送失败。

## 修复建议

将返回值检查改为 `ret < 0`，或对正常发送路径比较 `ret == reply->length`，并在失败时把错误返回给上层。`TransmitOfferOrAckPacket` 和 `SendDhcpNak` 应使用一致的处理方式。
