## 问题概述

DHCP Server 的 OFFER/ACK 发送函数 `TransmitOfferOrAckPacket` 与 NAK 发送函数 `SendDhcpNak` 都以 `if (!ret)` 判断 `sendto` 的返回值。POSIX `sendto` 在失败时返回 `-1`，而 `!-1` 为假，因此失败不会进入错误分支，函数会继续返回 `RET_SUCCESS`。

对于非空 DHCP 报文，成功返回值通常是正的已发送字节数；`0` 并不是这两个路径应当视为唯一失败值。现有检查既漏报 `-1`，又可能把零长度成功语义与失败混淆。

## 受影响发送路径

| 函数 | 报文类型 | 错误检查 |
| --- | --- | --- |
| `TransmitOfferOrAckPacket`，`dhcp_s_server.cpp:1620-1668` | OFFER 和 ACK | `if (!ret)` |
| `SendDhcpNak`，`dhcp_s_server.cpp:1710-1740` | NAK | `if (!ret)` |

两个位置的核心模式一致：

```cpp
int ret = sendto(srvIns->serverFd, &reply->packet, reply->length, 0,
    (struct sockaddr *)destAddrIn, sizeof(*destAddrIn));
if (!ret) {
    DHCP_LOGE("failed to send dhcp message.");
    return RET_FAILED;
}
return RET_SUCCESS;
```

当 `ret == -1` 时，条件为 false；调用者接到成功值，尽管数据报没有被发送。

## 正常调用路径与触发链

```text
服务端决定回复 DHCP OFFER / ACK / NAK
  │ 组装 reply 数据包
  ▼
TransmitOfferOrAckPacket 或 SendDhcpNak
  │ 调用 sendto(...)
  │ 底层返回 -1（例如套接字、接口或发送错误）
  │ if (!-1) 为 false
  ▼
函数返回 RET_SUCCESS
  ▼
上层记录或处理为“回复已发送”，客户端实际收不到数据包
```

### 最小触发条件

1. 服务端进入任一 DHCP 回复发送路径。
2. 已构造非空回复报文。
3. `sendto` 返回 `-1`。

验证通过真实 `TransmitOfferOrAckPacket` 构造一份可发送的回复，只在系统 `sendto` 边界返回 `-1`。函数实际返回 0（`RET_SUCCESS`），输出为 `sendto_return=-1 handler_result=0 expected_failure`。数据包准备和生产返回值判断均未被替换。

## 影响分析

### 直接行为

- OFFER、ACK 或 NAK 没有发送成功时，服务端仍返回成功。
- 上层失败处理、告警或重试无法依据返回值执行。
- 服务端日志可显示已完成回复，客户端则只看到超时。

### 用户可见后果

- DHCP 客户端可能重复 DISCOVER/REQUEST 或最终无法完成地址配置。
- 网络接口或套接字短暂异常时，服务端丢失了正确报告失败的机会。
- 故障排查中服务端与客户端状态相互矛盾，延长定位时间。

### 边界

本条证明的是系统调用返回负值时的处理错误。它不需要构造恶意报文，也不改变 DHCP 协议字段。实际发送失败的具体原因由操作系统与网络状态决定。

## 修复建议

至少以负值判断发送失败，并对完整写入进行校验：

```cpp
const int ret = sendto(...);
if (ret < 0 || ret != reply->length) {
    DHCP_LOGE("failed to send dhcp message.");
    return RET_FAILED;
}
return RET_SUCCESS;
```

两个函数应共享同一发送结果检查，避免其中一个路径修复后另一个仍保留相反逻辑。

## 回归测试建议

| 用例 | 注入结果 | 期望 |
| --- | ---: | --- |
| OFFER/ACK 成功发送 | `reply->length` | 返回 `RET_SUCCESS` |
| OFFER/ACK 失败 | `-1` | 返回 `RET_FAILED` |
| NAK 成功发送 | `reply->length` | 返回 `RET_SUCCESS` |
| NAK 失败 | `-1` | 返回 `RET_FAILED` |
| 非完整发送（若平台允许） | 小于 `reply->length` 的正值 | 返回失败并记录异常 |
