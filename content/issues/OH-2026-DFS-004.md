## 漏洞概述

`CloudDiskServiceCallbackImpl::OnChangeData` 为同步目录路径、`CloudDisk_ChangeData[]` 以及每项的字符串字段执行堆分配。函数调用应用注册的 C 回调后没有释放这些对象，公开接口也没有提供对应销毁函数或所有权转移约定。

## 根本原因

**位置**：`interfaces/kits/ndk/clouddiskmanager/src/oh_cloud_disk_manager.cpp`

```cpp
auto *changeData = new CloudDisk_ChangeData[data.size()];
// 为 path、uri、fileName 等字段继续分配内存
callback_(changeData, data.size());
// 返回前没有释放 changeData 及其字段
```

回调参数声明为 `const`。调用方既无法可靠判断所有权已经转移，也没有公共 API 可以释放内部创建的嵌套对象。

## 影响

- 每次目录变化通知都会在注册回调的应用进程中遗留堆对象。
- 长期监听并频繁产生文件变化时，进程内存占用会持续增长。
- 最终可能造成应用内存压力、回调处理失败或进程终止。

## 触发条件

应用注册 Cloud Disk 同步目录变化回调，并持续对该应用有权访问的同步目录产生变化事件。

## 修复建议

明确回调参数所有权。若参数仅在回调期间有效，应在回调返回后递归释放数组和字符串字段；若需要交给应用持有，应提供成对的公开销毁 API，并在接口文档中说明释放责任。
