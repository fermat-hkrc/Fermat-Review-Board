## 漏洞概述

`DiskMonitor` 启动一个分离的 FFRT 监控任务。任务无锁读取 `isRunning_`、`userId_`、`syncFolderPrefix_` 和 `blockList_`，停止路径却在 `mutex_` 下修改或清空这些字段并关闭描述符，而且没有等待监控任务退出。

## 根本原因

**位置**：`services/clouddiskservice/monitor/src/disk_monitor.cpp`

```cpp
ffrt::submit([this] { CollectEvents(); });

while (isRunning_) {              // 无锁读取
    // 使用 userId_、syncFolderPrefix_、blockList_
}

void DiskMonitor::StopMonitor()
{
    std::lock_guard lock(mutex_);
    isRunning_ = false;
    blockList_.clear();
    close(fanotifyFd_);
}
```

同一把锁只覆盖停止方，不能同步监控线程中的无锁读取；关闭描述符后也没有 join 或完成屏障保证使用已经结束。

## 影响

- 监控线程可能并发访问正在清空的字符串或 vector，产生未定义行为。
- 线程可能继续读取已经关闭的 fanotify 描述符。
- 可表现为错误过滤、监控提前终止或 Cloud Disk 服务崩溃。

## 触发条件

Cloud Disk 服务执行用户切换、重新初始化或停止监控时，监控线程仍在处理 fanotify 事件。

## 修复建议

使用同一同步机制保护全部共享字段。将运行标志改为受锁状态或原子变量，并在清空状态、关闭描述符前请求线程退出并等待任务结束。
