## 漏洞概述

CJ FFI 将 `NotificationLocalLiveViewContent` 转换为 `CNotificationSystemLiveViewContentV2` 时，把 `progress` 和 `time` 当作可选字段。转换函数仅在对应标志存在时填写局部结构，却无论标志是否存在都把整个结构复制到 FFI 返回对象。

当一条本地实况窗通知没有设置进度或时间时，`CNotificationProgressV2` 或 `CNotificationTimeV2` 的字段在源码层面没有值便被读取和复制。在未启用自动变量初始化的构建中，这属于 C++ 未定义行为，CJ 调用方可能收到原生栈上的残留字节或无效的状态值。

该转换路径由 `FfiOHOSNotificationManagerGetActiveNotifications` 使用，并编译进产品中的 `cj_notification_manager_ffi` 共享库。当前 `master` 提交 `c76a751c286e4e3fc614b4fccd57dfbfa13d2aa3` 仍存在该问题。本地可核对的 `OpenHarmony-v6.0-Release` 标签已包含相同实现；尚未确认已修复发行版。

## 根本原因

### 可选标志只控制赋值，不控制复制

**位置**: `frameworks/cj/ffi/src/notification_utils.cpp:1408`

```cpp
// progress: NotificationProgress
CNotificationProgressV2 cProgress;
if (localLiveViewContent->isFlagExist(
    NotificationLocalLiveViewContent::LiveViewContentInner::PROGRESS)) {
    NotificationProgress progress = localLiveViewContent->GetProgress();
    cProgress.maxValue = progress.GetMaxValue();
    cProgress.currentValue = progress.GetCurrentValue();
    cProgress.isPercentage = progress.GetIsPercentage();
}
systemLiveView->progress = cProgress;

// time: NotificationTime
CNotificationTimeV2 cTime;
if (localLiveViewContent->isFlagExist(
    NotificationLocalLiveViewContent::LiveViewContentInner::TIME)) {
    NotificationTime time = localLiveViewContent->GetTime();
    bool flag = localLiveViewContent->isFlagExist(
        NotificationLocalLiveViewContent::LiveViewContentInner::INITIAL_TIME);
    cTime.initialTime = flag ? time.GetInitialTime() : 0;
    cTime.isCountDown = time.GetIsCountDown();
    cTime.isPaused = time.GetIsPaused();
    cTime.isInTitle = time.GetIsInTitle();
}
systemLiveView->time = cTime;
```

`cProgress` 和 `cTime` 都没有值初始化。缺少 `PROGRESS` 或 `TIME` 标志时，相应条件体不会执行，但条件后的聚合赋值仍会读取局部结构的每个字段。

### 返回结构没有表达字段是否存在

**位置**: `frameworks/cj/ffi/include/notification_utils.h:92`

```cpp
struct CNotificationTimeV2 {
    int32_t initialTime;
    bool isCountDown;
    bool isPaused;
    bool isInTitle;
};

struct CNotificationProgressV2 {
    int32_t maxValue;
    int32_t currentValue;
    bool isPercentage;
};

struct CNotificationSystemLiveViewContentV2 {
    // ...
    CNotificationTimeV2 time;
    CNotificationProgressV2 progress;
};
```

FFI 结构使用内嵌值，没有 `hasTime`、`hasProgress` 或空指针来表示缺失状态。因此转换代码即使跳过赋值，也仍必须为返回字段提供确定内容。

实际调用链为：`FfiOHOSNotificationManagerGetActiveNotifications` → `NotificationManagerImplV2::GetActiveNotifications` → `SetNotificationRequestV2` → `SetNotificationContentV2` → `SetNotificationLocalLiveViewContentV2` → `SetNotificationLocalLiveViewContentDetailedV2`。`frameworks/cj/ffi/BUILD.gn` 将涉及文件全部编译进 `cj_notification_manager_ffi`，`bundle.json` 将该库作为组件 inner kit 发布。

## 影响

- CJ 调用方读取没有进度或时间的实况窗通知时，可能收到不确定的 `maxValue`、`currentValue`、`initialTime` 和布尔标志。
- 在没有自动变量初始化保护的构建中，复制未初始化结构可能把本进程原生栈的残留字节带到 FFI 调用方，并可能使上层按照虚假的计时或进度状态处理通知。
- OpenHarmony 标准 OHOS C++ target 默认将普通局部变量置零，且该共享库没有关闭这项保护。在该配置下，风险通常表现为无法区分“字段缺失”和合法的全零值，而不是稳定泄露栈内容。

该 FFI 转换发生在调用进程内，不是服务进程到应用进程的直接内存泄露。本次没有执行设备测试，也没有观察到具体栈字节、崩溃或权限边界变化。

## 触发条件

1. 当前应用存在一条 `LOCAL_LIVE_VIEW` 类型的活动通知。
2. 该通知没有 `PROGRESS`、`TIME` 中的至少一个可选标志，例如通知由其他语言绑定或系统组件创建时省略了相应字段。
3. CJ 调用 `FfiOHOSNotificationManagerGetActiveNotifications` 获取活动通知。
4. 转换函数跳过局部结构赋值，却仍把该结构复制到返回对象。

形成可观察的残留栈数据还要求目标构建未启用自动变量初始化。当前没有证据表明调用方可以控制残留内容。

## 修复建议

至少应对两个局部结构执行值初始化，使所有缺失路径返回确定的零值：

```cpp
CNotificationProgressV2 cProgress {};
if (localLiveViewContent->isFlagExist(
    NotificationLocalLiveViewContent::LiveViewContentInner::PROGRESS)) {
    // 填写有效进度。
}
systemLiveView->progress = cProgress;

CNotificationTimeV2 cTime {};
if (localLiveViewContent->isFlagExist(
    NotificationLocalLiveViewContent::LiveViewContentInner::TIME)) {
    // 填写有效时间。
}
systemLiveView->time = cTime;
```

如果 CJ API 需要保留可选语义，应在兼容的返回结构中增加明确的存在标志，或把可选字段改为可空指针。调用方不能通过字段恰好为零来判断字段不存在。
