## 漏洞概述

`GtBundleInstaller::RenameJsonFile` 先调用 `IsFile()` 检查源文件存在性，再调用 `RenameFile()` 执行重命名。检查与使用之间的竞争窗口允许攻击者替换源文件或目标路径，在 bundle 安装流程中注入恶意配置。

## 根本原因

**位置**: `services/bundlemgr_lite/src/gt_bundle_installer.cpp:811`

```cpp
bool GtBundleInstaller::RenameJsonFile(const char *oldPath, const char *newPath)
{
    if (!BundleFileUtils::IsFile(oldPath)) {  // CHECK: 验证源文件存在
        return false;
    }
    // 竞争窗口：攻击者可替换 oldPath 为恶意文件或 symlink

    if (!BundleFileUtils::RenameFile(oldPath, newPath)) {  // USE: 执行重命名
        return false;
    }
    return true;
}
```

**问题**:
1. `IsFile()` 与 `RenameFile()` 之间存在竞争窗口
2. 在 bundle 安装过程中调用，处理应用的 JSON 配置文件
3. 攻击者可替换临时 JSON 文件注入恶意 bundle 元数据
4. LiteOS-M 分支的 `RenameFile` 直接调用 `rename()` 无额外校验

## 影响

- 在 bundle 安装过程中注入恶意应用配置
- 篡改应用权限声明
- 可能导致权限提升（如注入系统权限声明）

## 触发条件

1. 目标处于 bundle 安装/更新流程中
2. 攻击者对临时文件目录有写权限
3. 在 `IsFile()` 检查通过后、`RenameFile()` 执行前
4. 攻击者将源路径替换为包含恶意配置的文件
5. 恶意配置被重命名为正式 bundle 配置文件

## 修复建议

```cpp
bool GtBundleInstaller::RenameJsonFile(const char *oldPath, const char *newPath)
{
-   if (!BundleFileUtils::IsFile(oldPath)) {
-       return false;
-   }
-   if (!BundleFileUtils::RenameFile(oldPath, newPath)) {
+   // 直接尝试 rename，原子操作无 TOCTOU
+   if (rename(oldPath, newPath) != 0) {
+       if (errno == ENOENT) {
+           return false;  // 源文件不存在
+       }
        return false;
    }
    return true;
}
```
