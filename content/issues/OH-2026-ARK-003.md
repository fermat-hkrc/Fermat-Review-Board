## 漏洞概述

`TLVUtil::ReadInt32()` 使用 7 位一组的变长编码读取 32 位整数，但没有限制编码最多只能占用 5 个字节。攻击者提供第 6 个编码字节时，函数会对 32 位整数执行至少 35 位的左移，产生 C++ 未定义行为。缺少终止字节时，函数还会把截断输入作为整数 `0` 返回，并将游标停留在缓冲区末尾，无法区分合法的零值和解析失败。

该解码器可以由 `StyledString.unmarshalling(ArrayBuffer)` 直接调用。在启用系统剪贴板支持时，ArkUI 还会将 `openharmony.styled-string` 自定义剪贴板记录直接交给同一解码器。因此，来自应用输入或剪贴板的数据能够到达缺少长度限制的整数解析逻辑。

受影响版本仅确认到当前 master commit `533810af82fc7314e6fc5c55a9ef5917b076654e`。仓库中的公开 tag 均早于该 TLV 实现，不能据此确定首个受影响的 OpenHarmony 发布版本。

## 根本原因

**位置**: `frameworks/core/components_ng/pattern/text/span/tlv_util.h:229`

```cpp
static int32_t ReadInt32(std::vector<uint8_t>& buff, int32_t& cursor)
{
    uint32_t value = 0;
    uint8_t shift = 0;
    uint32_t item = 0;
    do {
        if (static_cast<size_t>(cursor + 1) > buff.size()) {
            return static_cast<int32_t>(TLV_END);
        }
        item = uint32_t(buff[cursor++]);
        value |= (item & TLV_VARINT_MASK) << shift;
        shift += TLV_VARINT_BITS;
    } while ((item & TLV_VARINT_MORE) != 0);
    return static_cast<int32_t>(value);
}
```

每读取一个带 continuation bit 的字节，`shift` 增加 7。前 5 次移位量分别为 0、7、14、21 和 28；第 6 次变为 35，已经大于或等于 `uint32_t` 的位宽。代码没有在第 5 个字节验证高 4 位和 continuation bit，也没有在进入第 6 次循环前拒绝过长编码。

缓冲区耗尽时，函数返回 `TLV_END`。该常量值为 `0x00`，也是合法整数零。此时 `cursor` 不再推进，调用者无法判断收到的是零值还是截断的变长整数。对于包含额外字节的过长编码，函数还会继续消耗字节，导致后续 TLV 字段从错误位置开始解析。

**字符串调用路径**: `frameworks/core/components_ng/pattern/text/span/tlv_util.cpp:32`

```cpp

```

`ReadString()` 将不受限的解码结果直接作为字符串长度。`ReadU16String()` 只是该函数的包装；当前版本中没有独立的生产调用点。实际可达路径由 `SpanString::DecodeTlvOldExt()` 调用 `ReadString()` 形成。

**可达入口一**: `frameworks/bridge/declarative_frontend/style_string/js_span_string.cpp:998`


**可达入口二**: `adapter/ohos/capability/clipboard/clipboard_impl.cpp:529`

读取剪贴板时，自定义记录中的字节数组未经格式验证便进入 `DecodeTlv()`。因此，在应用读取或粘贴该记录时，恶意 styled-string 数据可以到达 `ReadInt32()`。

## 影响

- 解析包含至少 6 个变长整数编码字节的数据时，会执行超出 32 位宽度的左移，产生未定义行为。
- 解析结果可因编译器和处理器行为而变化，影响后续字符串长度、span 数量、类型和索引等字段。
- 过长或截断编码会破坏解析游标和字段边界，可导致 styled-string 解码失败或 UI 进程异常终止。
- 尚无证据表明该原语可以稳定造成受控内存破坏或任意代码执行。

## 触发条件

1. 攻击者能够控制传给 `StyledString.unmarshalling()` 的 `ArrayBuffer`；或者在系统剪贴板支持启用时，能够影响受害应用读取的 `openharmony.styled-string` 自定义记录。
2. TLV 数据进入需要读取 32 位整数的字段，例如字符串长度或 span 数量。
3. 该字段使用超过 5 个字节的变长编码，或在 continuation bit 仍置位时到达缓冲区末尾。
4. 受害应用执行 styled-string 反序列化或读取、粘贴对应剪贴板记录。

## 修复建议

将变长整数限制为最多 5 个字节，并在移位前验证第 5 个字节只能包含 32 位整数剩余的低 4 位。解析接口应通过独立返回值传递失败状态，避免将截断输入与合法整数 `0` 混为一谈。
