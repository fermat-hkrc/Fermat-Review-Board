## 漏洞概述

`StyledString` 的 TLV 解码器直接使用输入中的 32 位集合计数控制循环，只拒绝负数，没有根据剩余数据长度限制计数，也没有在元素解析失败或游标停止推进时终止循环。一个很短的 TLV 缓冲区可以声明最多 `INT32_MAX` 个字体族、文本阴影、文本装饰、字体特性或渐变色元素。

当输入在计数字段后提前结束时，底层读取函数返回 `TLV_END`，但不推进游标。集合读取函数仍按声明数量继续循环。其中四类读取会不断向容器插入默认对象，造成 CPU 和内存资源耗尽；渐变色读取不会在 EOF 时插入对象，但仍会执行全部循环，造成长时间 CPU 占用。

本条仅确认当前 master commit `d8847980b8c1fdbb6e79b5a9b641cabde4ba9a70` 受影响。现有仓库 tag 无法将相关提交可靠映射到公开发布版本，因此不声明更早的受影响版本或已修复版本。

受影响数据可以通过 `StyledString.unmarshalling(ArrayBuffer)` 进入解码器。在启用系统剪贴板支持的构建中，`ClipboardImpl` 还会将自定义类型 `openharmony.styled-string` 的剪贴板数据直接传给同一解码器。因此，处理来自文件、网络、剪贴板或其他不可信数据源的 StyledString 时，目标应用进程可能卡死或因内存耗尽终止。

## 根本原因

**位置**: `frameworks/core/components_ng/pattern/text/span/tlv_util.cpp:153`

`ReadFontFamily()` 只检查计数是否为负数，然后无条件执行 `fontFamilySize` 次循环：

```cpp
int32_t fontFamilySize = ReadInt32(buff, cursor);
if (fontFamilySize < 0) {
    return fontFamilies;
}
for (auto i = 0; i < fontFamilySize; i++) {
    auto fontFamily = ReadString(buff, cursor);
    fontFamilies.emplace_back(fontFamily);
}
```

相同的计数处理模式还存在于以下函数中：

| 函数 | 计数字段 | EOF 后的行为 |
|---|---|---|
| `ReadFontFamily()` | `fontFamilySize` | 重复插入空字符串 |
| `ReadTextShadows()` | `shadowSize` | 重复插入默认 `Shadow` 对象 |
| `ReadTextDecorations()` | `size` | 重复插入值为 0 的枚举 |
| `ReadFontFeature()` | `len` | 重复向链表插入空字符串和 0 |
| `ReadGradientColors()` | `size` | 不插入元素，但持续执行剩余循环 |

**位置**: `frameworks/core/components_ng/pattern/text/span/tlv_util.h:211`

缓冲区耗尽时，基础读取函数将 EOF 映射为数值 0，并保持 `cursor` 不变。调用方无法区分“成功读取到 0”和“读取失败”：

```cpp
static uint8_t ReadUint8(std::vector<uint8_t>& buff, int32_t& cursor)
{
    if (static_cast<size_t>(cursor + 1) > buff.size()) {
        return TLV_END;
    }
    return buff[cursor++];
}

static int32_t ReadInt32(std::vector<uint8_t>& buff, int32_t& cursor)
{
    // ...
    if (static_cast<size_t>(cursor + 1) > buff.size()) {
        return static_cast<int32_t>(TLV_END);
    }
    // ...
}
```

`ReadFontFamily()`、`ReadTextShadows()`、`ReadTextDecorations()` 和 `ReadFontFeature()` 因此会在 EOF 后继续插入默认值。`ReadGradientColors()` 在读取不到 `TLV_SPAN_TEXT_LINE_STYLE_GRADIENT_COLOR` 标签时执行 `continue`，同样不会检查 EOF 或游标是否推进：

```cpp
for (auto i = 0; i < size; i++) {
    if (ReadUint8(buff, cursor) != TLV_SPAN_TEXT_LINE_STYLE_GRADIENT_COLOR) {
        continue;
    }
    // ...
}
```

入口路径没有在解析前验证 TLV 结构。`JSSpanString::Unmarshalling()` 接受 `ArrayBuffer`，复制其全部字节后异步调用 `SpanString::DecodeTlv()`。在系统剪贴板路径中，`ClipboardImpl::GetDataSync()` 对 `openharmony.styled-string` 自定义记录执行相同的解码操作。

## 影响

- `ReadFontFamily()`、`ReadTextShadows()`、`ReadTextDecorations()` 和 `ReadFontFeature()` 可产生与实际输入长度不成比例的容器增长，最终导致内存耗尽、异常终止或应用进程被系统回收。
- 五个读取函数均可执行最多 `INT32_MAX` 次循环，长时间占用工作线程或剪贴板同步任务，导致 StyledString 解析、粘贴流程或目标应用无响应。
- 当前源码证据支持应用进程级拒绝服务。未确认内存破坏、代码执行或系统级拒绝服务。

## 触发条件

1. 数据生产方能够向目标应用提供 StyledString TLV 数据，例如目标应用对不可信 `ArrayBuffer` 调用 `StyledString.unmarshalling()`，或目标应用读取包含 `openharmony.styled-string` 自定义记录的系统剪贴板。
2. TLV 中包含一个能够到达上述集合读取函数的 SpanItem 样式字段。
3. 集合计数字段编码为很大的正整数，但后续元素数量不足，或者输入在计数字段后结束。
4. 解码器按声明数量继续循环，且在 EOF 后不终止。

剪贴板路径要求构建时启用系统剪贴板支持，并要求目标应用实际读取或粘贴该记录。直接调用 `StyledString.unmarshalling()` 的路径不依赖剪贴板支持。

## 修复建议

1. 将基础读取接口改为显式返回成功或失败状态，避免使用合法数值 `TLV_END` 表示 EOF。
2. 读取集合计数后，同时校验非负值、组件允许的最大元素数量以及剩余缓冲区能否容纳相应数量的最小编码元素。
3. 每次解析元素后检查游标是否向前推进。遇到 EOF、标签错误、截断的元素或游标不变时，应立即返回解析错误，不应向容器插入默认对象。
4. 在 `StyledString.unmarshalling()` 和剪贴板入口增加 StyledString 编码总长度上限，作为集合级检查之外的第二层限制。

可先增加统一的剩余长度检查，防止小缓冲区声明超大集合：

```diff
+static bool IsValidCollectionCount(
+    const std::vector<uint8_t>& buff, int32_t cursor, int32_t count)
+{
+    if (cursor < 0 || count < 0 || static_cast<size_t>(cursor) > buff.size()) {
+        return false;
+    }
+    // 每个合法集合元素至少消耗一个字节；各读取函数还应使用其实际最小编码长度。
+    return static_cast<size_t>(count) <= buff.size() - static_cast<size_t>(cursor);
+}

 int32_t fontFamilySize = ReadInt32(buff, cursor);
-if (fontFamilySize < 0) {
+if (!IsValidCollectionCount(buff, cursor, fontFamilySize)) {
     return fontFamilies;
 }
 for (auto i = 0; i < fontFamilySize; i++) {
+    auto previousCursor = cursor;
     auto fontFamily = ReadString(buff, cursor);
+    if (cursor <= previousCursor) {
+        return {};
+    }
     fontFamilies.emplace_back(fontFamily);
 }
```

上述检查应分别应用到 `ReadTextShadows()`、`ReadTextDecorations()`、`ReadFontFeature()` 和 `ReadGradientColors()`。生产修复还应为每种集合定义符合 StyledString 语义的独立最大数量，而不是只依赖通用的一字节下界。

建议增加以下回归测试：

- 最大合法集合能够正常解码。
- 计数大于剩余字节数时立即失败。
- 元素在中间截断时立即失败，游标不再推进时不会继续循环。
- `INT32_MAX` 计数配合空元素区时，不发生大规模循环或容器增长。
- JS `StyledString.unmarshalling()` 和剪贴板自定义记录均能拒绝相同的畸形 TLV。
