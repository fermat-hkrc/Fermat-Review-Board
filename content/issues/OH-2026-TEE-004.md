## 漏洞概述

`get_proc_node()` 在哈希表中查找进程节点后释放 `proc_nodes_lock`，然后返回裸指针给调用者。在锁释放后、调用者使用指针之前，另一线程可通过进程退出路径执行 `free_proc_node_resource(proc); free(proc);` 释放同一节点。调用者后续对该指针的任何访问均为 Use-After-Free。

## 根本原因

**位置**: `procmgr/proc_node.c:246`

```c
struct proc_node *get_proc_node(badge_t client_badge)
{
    struct proc_node *proc;
    struct hlist_head *buckets;

    pthread_mutex_lock(&proc_nodes_lock);
    buckets = htable_get_bucket(&badge2proc, client_badge);

    for_each_in_hlist (proc, hash_node, buckets) {
        if (client_badge == proc->badge) {
            goto out;
        }
    }
    pthread_mutex_unlock(&proc_nodes_lock);
    return NULL;
out:
    pthread_mutex_unlock(&proc_nodes_lock);  // ← 释放锁
    return proc;                              // ← 返回可能被释放的指针
}
```

**问题**:
1. 指针 `proc` 指向堆内存中的 `struct proc_node`
2. 锁释放后该节点不再受保护
3. 进程退出时 `recycle_proc_node` → `free_proc_node_resource` → `free(proc)` 释放节点
4. 调用者持有的指针变为悬空指针

## 影响

- **TEE 内核崩溃**：解引用已释放内存触发段错误或数据异常
- **权限提升**：攻击者通过堆喷射控制已释放内存内容，伪造 proc_node 结构体中的权限/badge 字段
- **信息泄露**：已释放内存可能被重新分配给其他数据结构，读取泄露敏感信息

## 触发条件

1. 线程 A 通过 IPC 请求触发 `get_proc_node(badge)` 查找进程节点
2. 线程 B 同时处理该进程的退出事件（如 TA 崩溃/正常退出）
3. 线程 A 获得指针后，线程 B 获取锁并释放该节点
4. 线程 A 后续访问节点字段（如 `proc->pid`、`proc->cap_group`）触发 UAF

## 修复建议

引入引用计数，确保节点在使用期间不被释放：

```c
struct proc_node *get_proc_node(badge_t client_badge)
{
    struct proc_node *proc;
    struct hlist_head *buckets;

    pthread_mutex_lock(&proc_nodes_lock);
    buckets = htable_get_bucket(&badge2proc, client_badge);

    for_each_in_hlist (proc, hash_node, buckets) {
        if (client_badge == proc->badge) {
            atomic_fetch_add(&proc->refcount, 1);  // 增加引用计数
            pthread_mutex_unlock(&proc_nodes_lock);
            return proc;
        }
    }
    pthread_mutex_unlock(&proc_nodes_lock);
    return NULL;
}

// 调用者使用完毕后:
void put_proc_node(struct proc_node *proc) {
    if (atomic_fetch_sub(&proc->refcount, 1) == 1) {
        free_proc_node_resource(proc);
        free(proc);
    }
}
```
