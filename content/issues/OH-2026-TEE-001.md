## 漏洞概述

`WriteSingleFile()` 先调用 `JudgeFileValidite()` 通过 `lstat()` 验证文件为普通文件并获取大小，再调用 `WriteZipContent()` 通过 `tee_open()`（内部为 `open()` 且无 `O_NOFOLLOW`）打开文件读取内容写入 gzip 压缩包。检查与使用之间存在竞争窗口，攻击者可将日志文件替换为指向敏感文件的符号链接，使 tlogcat 将目标文件内容泄露到可读的压缩包中。

## 根本原因

**位置**: `services/tlogcat/src/tarzip.c:221`

```c
static int32_t WriteSingleFile(const char *fileName, gzFile out)
{
    struct stat fileAttr = {0};

    if (!JudgeFileValidite(fileName, &fileAttr)) {  // CHECK: lstat() 验证 S_ISREG
        return 0;
    }

    // ... strrchr + WriteHeader ...

    WriteZipContent(out, fileName, fileAttr.st_size);  // USE: tee_open() 无 O_NOFOLLOW
    return 0;
}
```

`WriteZipContent` 内部调用:

```c
static void WriteZipContent(gzFile gzFd, const char *fileName, long fileSize)
{
    int32_t fileFd = tee_open(fileName, O_CREAT | O_RDWR, ZIP_OPEN_MODE);
    // tee_open 是 open() 的封装，不使用 O_NOFOLLOW
    // 如果 fileName 已被替换为 symlink，open() 会跟随链接打开目标文件
    ...
}
```

**问题**:
1. `JudgeFileValidite()` 使用 `lstat()` 检查（不跟随符号链接）
2. `tee_open()` 使用 `open()` 打开（跟随符号链接）
3. 两次操作之间存在竞争窗口，攻击者可将文件替换为 symlink

## 影响

- 任意文件读取：敏感文件内容被写入 gzip 压缩包
- 压缩包权限为 `S_IRUSR | S_IRGRP`，同组用户可读取泄露内容
- 可泄露 TEE 安全存储数据、密钥材料、其他服务的私有数据

## 触发条件

1. 攻击者拥有对 `/data/log/tee/` 目录的写权限（需 tee uid/gid 或 system group）
2. tlogcat 正在执行日志压缩（日志文件达到 500KB 时自动触发 `TarZipFiles()`）
3. 在 `lstat()` 返回之后、`tee_open()` 执行之前的窗口内
4. 将日志文件替换为指向目标敏感文件的符号链接
5. `tee_open()` 跟随 symlink 打开目标文件，内容写入压缩包

## 修复建议

```c
static void WriteZipContent(gzFile gzFd, const char *fileName, long fileSize)
{
-   int32_t fileFd = tee_open(fileName, O_CREAT | O_RDWR, ZIP_OPEN_MODE);
+   int32_t fileFd = tee_open(fileName, O_RDONLY | O_NOFOLLOW, ZIP_OPEN_MODE);
+   if (fileFd < 0) {
+       return;  // O_NOFOLLOW 会使 symlink 打开失败 (ELOOP)
+   }
    ...
}
```

或使用 `openat` 方案：

```c
int dirfd = open(parent_dir, O_RDONLY | O_DIRECTORY);
int fileFd = openat(dirfd, basename, O_RDONLY | O_NOFOLLOW);
```
