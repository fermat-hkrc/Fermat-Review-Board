## 漏洞概述

`AniEnv::array_buffer()` 通过 FFI vtable 调用 `ArrayBuffer_GetInfo` 获取 ArrayBuffer 的数据指针和大小。函数检查了返回码是否为 0（成功），但未验证输出指针 `ptr` 是否为 null，直接将其传入 `std::slice::from_raw_parts(ptr, size)`。当 ANI 运行时对 detached ArrayBuffer 返回成功但 ptr 保持 null 时，产生未定义行为，访问时触发 SIGSEGV 导致 netmanager 服务崩溃。

## 根本原因

**位置**: `common/ani_rs/src/env.rs:843`

```rust
pub fn array_buffer(&self, array: &AniRef<'local>) -> Result<&'local [u8], AniError> {
    let mut ptr = null_mut() as *mut c_void;
    let mut size = 0usize;
    let res = unsafe {
        (**self.inner).ArrayBuffer_GetInfo.unwrap()(
            self.inner,
            array.as_raw(),
            &mut ptr as _,
            &mut size as *mut _,
        )
    };

    if res != 0 {
        let msg = String::from("Failed to get array buffer");
        Err(AniError::from_code(msg, res))
    } else {
        // BUG: 未检查 ptr 是否为 null
        unsafe { Ok(std::slice::from_raw_parts(ptr as *const u8, size)) }
    }
}
```

**问题**:
1. `ArrayBuffer_GetInfo` 返回 0（成功）但 `ptr` 仍为 null（detached buffer 场景）
2. `std::slice::from_raw_parts(null, size)` 当 size > 0 时为未定义行为
3. 访问返回的 slice 时触发 SIGSEGV

**对比**: 同文件 `typed_array.rs:104` 正确实现了 null 检查：

```rust
if self.data_ptr.is_null() {
    return &mut [];
}
```

## 影响

- netmanager 服务崩溃（DoS）
- 影响网络管理功能可用性
- 可由应用层通过传入 detached ArrayBuffer 触发

## 触发条件

1. ArkTS/JavaScript 代码创建 ArrayBuffer
2. 通过 `transferArrayBuffer` 或 structured clone 分离 ArrayBuffer 所有权
3. 将 detached ArrayBuffer 引用传给调用 `env.array_buffer()` 的 native 方法
4. ANI runtime 的 `ArrayBuffer_GetInfo` 返回 0 但 ptr 为 null
5. `from_raw_parts(null, size)` 产生 UB，后续访问触发 SIGSEGV

## 修复建议

```rust
    } else {
+       if ptr.is_null() {
+           let msg = String::from("ArrayBuffer data pointer is null");
+           return Err(AniError::from_code(msg, -1));
+       }
        unsafe { Ok(std::slice::from_raw_parts(ptr as *const u8, size)) }
    }
```
