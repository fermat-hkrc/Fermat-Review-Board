## 漏洞概述

`RtcpHeader::GetPaddingSize()` 读取偏移量 `GetSize() - 1` 处的字节，其中 `GetSize()` 返回 `(1 + ntohs(length_)) << 2`。`length_` 是 RTCP 包头中的 16 位字段，完全由网络数据控制，未验证与实际缓冲区大小的关系。

攻击者构造的 RTCP 包设置 `padding_ = 1` 和 `length_ = 100`，使 `GetSize()` 返回 404。函数读取偏移量 403 处的字节，而实际缓冲区可能只有 4 字节，导致堆越界读取 399 字节。

## 问题代码

```cpp
// rtcp.cpp:39-46
int32_t RtcpHeader::GetPaddingSize() const
{
    if (!padding_) {
        return 0;
    }
    return ((uint8_t *)this)[GetSize() - 1];  // GetSize() 不验证缓冲区边界
}
```

`GetSize()` 实现：

```cpp
// rtcp.h:42
int32_t GetSize() const { return (1 + ntohs(length_)) << 2; }  // length_ 来自网络
```

## 触发条件

1. 接收 RTCP 包（WiFi Display 协议栈）
2. 包头设置 padding 位（`padding_ = 1`）
3. length 字段设置为大值（如 100 → GetSize()=404）
4. 实际包长度远小于 GetSize() 声称的长度
5. 调用 GetPaddingSize() 或间接通过 GetFciSize() 触发

触发路径：

```
接收 RTCP 包 → RtcpHeader* overlay
→ padding_=1, length_=100 (attacker-controlled)
→ GetSize() = (1 + 100) * 4 = 404
→ GetPaddingSize() reads at offset 403
→ 实际分配仅 4 字节 → heap-buffer-overflow (399 bytes past allocation)
```

## 影响

- **堆越界读取**：攻击者通过 length 字段控制读取偏移量（最大 262143 字节偏移）
- **信息泄露**：越界读取可泄露堆上其他分配的内存内容
- **级联影响**：GetPaddingSize() 的返回值被 GetFciSize() 使用，影响 RTCP FB 包解析
- **影响范围**：RTCP 是 RTP 会话控制协议，所有 WiFi Display 连接都使用

## 同模块其他 OOB 漏洞

该模块有系统性设计问题：所有 Get*() 方法基于包头字段迭代或计算指针，但不验证缓冲区实际长度。

| 函数 | 漏洞 | CWE |
|------|------|-----|
| `RtcpSR::GetItemList()` | 基于 reportCount_ 迭代，不检查缓冲区 | CWE-125 |
| `RtcpRR::GetItemList()` | 同上 | CWE-125 |
| `RtcpBye::GetSSRC()` | ssrc_[i] 越界读取 | CWE-125 |
| `RtcpBye::GetReason()` | 使用 GetSize() 作为边界检查（攻击者控制） | CWE-125 |
| `RtcpSdes::GetChunkList()` | 不受信循环计数 + 不受信步长 | CWE-125 |
| `RtcpXRDLRR::GetItemList()` | blockLength_ 未验证 | CWE-125 |
| `RtcpSR::Create()` | itemCount * sizeof(ReportItem) 整数溢出 | CWE-190 |

## 修复建议

```diff
 int32_t RtcpHeader::GetPaddingSize() const
 {
     if (!padding_) {
         return 0;
     }
+    int32_t size = GetSize();
+    // Validate size is within reasonable bounds
+    if (size <= 0 || size > RTCP_MAX_PACKET_SIZE) {
+        return 0;
+    }
     return ((uint8_t *)this)[GetSize() - 1];
 }
```

更根本的修复：所有 Get*() 方法应接收 `buffer_size` 参数并验证字段值不超出缓冲区范围。
