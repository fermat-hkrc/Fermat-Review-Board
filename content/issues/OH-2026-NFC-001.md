## 问题概述

NFC Tag 服务端完成 `WriteNdefTag` 后，把输入数据长度写入 IPC reply；客户端则把 reply 中的同一整数解释为 `ErrCode`。因此服务实际写入成功时，调用方仍会收到由数据长度转换而来的错误结果。

## 根本原因

服务端已经取得真实返回值 `ret`，但写入 reply 的是 `dataLen`：

```cpp
ErrCode ret = WriteNdefTag(dataToWrite);
reply.WriteInt32(dataLen);
return ret;
```

客户端按结果码读取该字段：

```cpp
return ErrCode(reply.ReadInt32());
```

IPC 两端对字段含义的定义不一致。

## 影响

- 有效 NDEF 数据可以写入成功，但应用收到错误结果。
- 应用可能错误提示写入失败，或进行不必要的重试。
- 返回结果随数据长度变化，无法反映真实服务执行状态。

## 触发条件

1. 应用通过正常接口调用 `WriteNdefTag`。
2. 输入为长度大于 0 且不超过上限的有效 NDEF 数据。
3. 服务端 `WriteNdefTag` 返回成功。
4. 客户端读取 reply，并把数据长度转换为 `ErrCode`。

## 修复建议

服务端应写入真实返回值，并保持 proxy 与 stub 的字段定义一致：

```cpp
ErrCode ret = WriteNdefTag(dataToWrite);
reply.WriteInt32(static_cast<int32_t>(ret));
return ret;
```
