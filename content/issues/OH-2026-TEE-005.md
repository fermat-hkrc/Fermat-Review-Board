## 漏洞概述

`dead()` 函数作为未识别 syscall 的处理入口，直接将用户态传入的 syscall 号 `n` 强制转换为指针并写入零值。TEE 中的恶意 TA 可通过调用一个未支持的 syscall 号（其值为目标内存地址），在 TEE 内核地址空间中任意位置写入零。

## 根本原因

**位置**: `chcore-port/syscall_dispatcher.c:933`

```c
void dead(long n)
{
    printf("Unsupported syscall %d, bye.\n", n);
    volatile int *addr = (int *)n;   // ← 用户可控的 n 被直接转为指针
    *addr = 0;                        // ← 向该地址写入 0
}
```

在 `__syscall6` 的 default 分支中调用：

```c
long __syscall6(long n, long a, long b, long c, long d, long e, long f)
{
    switch (n) {
    case SYS_read: ...
    case SYS_write: ...
    // ...
    default:
        dead(n);                      // ← 未识别的 syscall 号传入
        return chcore_syscall6(n, a, b, c, d, e, f);
    }
}
```

**问题**:
1. `n` 是 TA 传入的 syscall 号，完全由用户态控制
2. `dead()` 将 `n` 直接强转为 `int *` 并解引用写零
3. 没有任何地址合法性检查
4. TEE 内核与 TA 共享地址空间（或 TA 可构造内核态映射地址）

## 影响

- **任意地址写零**：攻击者可将 TEE 内核中任何可写地址清零
- **安全标志清除**：将访问控制标志/权限位写零以绕过安全检查
- **内核数据结构损坏**：清零关键内核指针导致 TEE 内核崩溃
- **权限提升**：通过精确清零 capability/权限字段实现 TA 提权

## 触发条件

1. 恶意 TA 在 TEE 环境中运行
2. TA 调用 `syscall(TARGET_ADDR, ...)` 其中 `TARGET_ADDR` 是目标内核地址
3. `__syscall6` 的 switch 无法匹配该值，进入 default 分支
4. `dead(TARGET_ADDR)` 执行 `*(int *)TARGET_ADDR = 0`
5. 目标地址被写零

## 修复建议

移除 `dead()` 中的危险解引用，改为安全的错误处理：

```c
void dead(long n)
{
    printf("Unsupported syscall %ld, terminating TA.\n", n);
    // 终止调用方 TA，不执行任何内存写入
    exit_current_task(TASK_EXIT_KILLED);
    __builtin_unreachable();
}
```
