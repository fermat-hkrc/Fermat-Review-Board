## 问题概述

DHCP 客户端支持 Option Overload，并会把当前解析指针切换到报文的 `file` 或 `sname` 字段。但是每轮校验仍固定读取 `packet->options`，因此无法正确解析被放入扩展字段的有效选项。

## 根本原因

主循环维护了当前字段指针 `pOption`：

```cpp
if ((nFlag == OPTION_FIELD) && (nOver & FILE_FIELD)) {
    pOption = packet->file;
    nIndex = 0;
    maxLen = DHCP_BOOT_FILE_LENGTH;
}
```

但 `CheckOptionsData` 忽略当前指针，始终重新使用主 options 区域：

```cpp
const uint8_t *pOption = packet->options;
if (pOption[index + DHCP_OPT_CODE_INDEX] != code) {
    return DHCP_OPT_NULL;
}
```

## 影响

- 位于 `file` 或 `sname` 扩展字段中的 DNS、路由等选项可能被忽略。
- 客户端可能取得 IP 地址，但缺少服务端提供的有效网络配置。
- 使用 Option Overload 的标准 DHCP 服务端与该客户端存在互操作问题。

## 触发条件

1. DHCP 服务端返回合法的 Option Overload 选项 52。
2. 选项值指定 `file`、`sname` 或两者承载额外选项。
3. 客户端查询只存在于扩展字段中的选项。

## 修复建议

让 `CheckOptionsData` 接收当前字段指针，或直接在主循环中基于 `pOption` 完成边界和代码校验，不能重新固定到 `packet->options`。
