## 漏洞概述

`UnlinkRecursive()` 先调用 `lstat()` 判断路径是文件还是目录，然后调用 `unlink()` 或 `opendir()` 执行删除。在 `lstat()` 和后续操作之间存在竞争窗口。对于目录路径，`opendir()` 跟随符号链接，攻击者可将路径替换为指向其他目录的 symlink，导致 teecd 递归删除非预期的目录树。

## 根本原因

**位置**: `services/teecd/src/fs_work_agent.c:697`

```c
static int32_t UnlinkRecursive(const char *name)
{
    struct stat st;

    if (lstat(name, &st) < 0) {       // CHECK: 判断文件类型
        return -1;
    }

    if (!S_ISDIR(st.st_mode)) {
        if (unlink(name) < 0) {        // USE (文件): 直接 unlink
            return -1;
        }
        return 0;
    }

    return UnlinkRecursiveDir(name);   // USE (目录): opendir 跟随 symlink
}
```

`UnlinkRecursiveDir` 中 `opendir(name)` 会跟随符号链接，遍历并删除目标目录的内容：

```c
static int32_t UnlinkRecursiveDir(const char *name)
{
    DIR *dir = opendir(name);  // 跟随 symlink → 打开错误的目录
    // ... 遍历目录项 ...
    // 对每个子项递归调用 UnlinkRecursive
    rmdir(name);
}
```

**问题**:
1. `lstat()` 检查路径类型（不跟随 symlink）
2. `opendir()` 跟随 symlink，打开攻击者指定的目录
3. 递归删除整个目标目录树

## 影响

- 任意目录树递归删除
- 可删除其他 TA 的安全存储数据
- 可造成系统服务异常（删除关键配置/数据目录）

## 触发条件

1. 攻击者对 `/sec_storage/` 或 `/data/service/el1/public/sec_storage_data/` 有写权限
2. 这些目录权限为 700，owner 为 tee 用户（攻击者需具备 tee uid/gid）
3. TEE 内核通过 ioctl 发送 SEC_REMOVE 命令触发删除操作
4. 在 `lstat()` 返回之后、`opendir()` 执行之前的窗口内
5. 将目标路径替换为指向受害目录的符号链接

**注**: 可利用性较低——文件路径来源于 TEE 内核（Secure World），非普通应用可控。实际利用需先获取 tee 用户权限或 TEE 内核控制权。作为代码质量和纵深防御问题报告。
