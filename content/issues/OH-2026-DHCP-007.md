## 问题概述

在定义 `OHOS_ARCH_LITE` 的构建中，DHCP 原生框架的三个生产翻译单元包含与其 Lite 头文件或本地声明不一致的标识符和表达式。它们在语义编译阶段即被拒绝，因而 Lite 目标无法构建并到达运行测试。

本条是一个构建可用性问题，列出的错误均能在实际 Lite 条件分支中稳定复现；它不依赖扫描器推断，也不依赖运行时输入。

## 受影响翻译单元

| 文件 | 位置 | 实际不一致 | 编译后果 |
| --- | --- | --- | --- |
| `dhcp_server_impl.cpp` | 56-70 | 声明 `serverProxy`，却使用 `clientProxy` | `clientProxy` 未声明 |
| `dhcp_server_callback_stub_lite.cpp` | 25 | 头文件成员为 `callback_`，构造函数初始化 `userCallback_` | 不存在的成员初始化 |
| 同上 | 135 | `IpcIo *data` 使用 `data.GetRawDataSize()` | 指针采用对象访问，成员不存在 |
| 同上 | 138 | 已读入 `stateCode`，却调用 `OnServerStatusChanged(state)` | `state` 未声明 |
| `dhcp_server_proxy_lite.cpp` | 153 | 定义 `WifiScanProxy::OnRemoteDied` | `WifiScanProxy` 不是该实现声明的类 |
| 同上 | 207 及后续 | 使用 `mRemoteDied` | Lite proxy 成员为 `remoteDied_` |

## 根本原因

### 1. 变量名漂移

```cpp
DhcpServerProxy *serverProxy = DhcpServerProxy::GetInstance();
if (serverProxy == nullptr) {
    return false;
}
if (clientProxy == nullptr) {       // 未声明
    return false;
}
client_ = clientProxy;              // 未声明
```

### 2. Lite callback 实现与头文件不同步

头文件的 Lite 私有成员是 `callback_`，实现却使用 `userCallback_`；同一实现又将 `IpcIo *` 当作拥有成员函数的 C++ 对象：

```cpp
DhcpServreCallBackStub::DhcpServreCallBackStub() : userCallback_(nullptr), mRemoteDied_(false)
{
}
// ...
DHCP_LOGI("... %{public}zu", data.GetRawDataSize());
int stateCode = 0;
(void)ReadInt32(data, &stateCode);
OnServerStatusChanged(state);
```

### 3. Lite proxy 使用标准或旧类名和成员名

```cpp
void WifiScanProxy::OnRemoteDied(void)
{
    remoteDied_ = true;
}

DHCP_LOGI("... %{public}d", mRemoteDied);
```

实际 Lite 类为 `DhcpServerProxy`，且构造函数初始化的是 `remoteDied_`。

## 构建路径与触发条件

```text
Lite 产品或组件构建
  │ 定义 OHOS_ARCH_LITE
  ▼
编译 DHCP native framework 源文件
  ├─ dhcp_server_impl.cpp
  ├─ dhcp_server_callback_stub_lite.cpp
  └─ dhcp_server_proxy_lite.cpp
  ▼
编译器进入 Lite 条件分支
  ▼
在未声明标识符、错误成员名和错误指针表达式处停止
```

### 最小触发条件

1. 以 Lite 配置定义 `OHOS_ARCH_LITE`。
2. 编译上述任一生产 `.cpp` 文件，而不是只编译标准分支。
3. 使用与项目头文件相匹配的最小 Lite 平台声明。

验证对三份真实翻译单元分别执行语法检查。三个单元均被编译器拒绝，输出包含 `clientProxy`、`GetRawDataSize`、`state`、`WifiScanProxy` 和 `mRemoteDied` 对应诊断。

## 影响分析

### 直接行为

- DHCP Lite 组件无法完成编译。
- 无论运行时是否会调用这些函数，翻译单元都会在构建阶段失败。
- 下游 Lite 产品集成 DHCP 服务时会被阻塞。

### 工程影响

- 标准版本构建成功不能证明 Lite 分支可用。
- 由于错误散布在初始化、回调与 proxy 文件，单个临时修补不能替代完整 Lite 配置构建。
- 没有独立 Lite 编译测试时，标准分支重构容易再次引入同类名称漂移。

### 边界

本条仅声明 Lite 编译条件下的可复现失败；它不对未定义 `OHOS_ARCH_LITE` 的标准构建作负面结论。

## 修复建议

1. `DhcpServerImpl::Init` 全程使用已声明的 `serverProxy`，并将其赋给 `client_`。
2. 让 Lite callback 实现使用头文件的 `callback_`，将 `data.GetRawDataSize()` 改为适用于 `IpcIo *` 的表达式或删去该日志字段，并把 `state` 改为 `stateCode`。
3. 将 `WifiScanProxy::OnRemoteDied` 改为实际声明的 `DhcpServerProxy::OnRemoteDied`，所有 `mRemoteDied` 改为 `remoteDied_`。
4. 在持续构建中单独编译 Lite 翻译单元，不能只依赖标准配置。

## 回归测试建议

| 用例 | 期望 |
| --- | --- |
| `OHOS_ARCH_LITE` 语法编译三个受影响单元 | 全部通过，无未声明标识符 |
| Lite `DhcpServerImpl::Init` | 使用正确 proxy 指针，初始化结果符合返回值 |
| Lite status callback | 从 `IpcIo *` 读取 `stateCode` 并分发该值 |
| Lite remote-death 处理 | 正确更新 `remoteDied_` 并通知 callback stub |
| 标准构建 | 现有标准分支保持通过 |
