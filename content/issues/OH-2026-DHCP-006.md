## 问题概述

`interfaces/kits/c` 下的公开头文件无法被标准 C 编译器包含。C 结构体使用了未声明的 `bool`，函数声明还使用 C++ 引用和默认参数。

## 根本原因

以下声明属于 C++ 语法，不能出现在 C API 头文件中：

```cpp
bool isOptSuc;
DhcpErrorCode StartDhcpClient(const RouterConfig &config);
DhcpErrorCode DealWifiDhcpCache(int32_t cmd, const IpCacheInfo &ipCacheInfo);
DhcpErrorCode StopDhcpClient(const char *ifname, bool bIpv6, bool bIpv4 = true);
```

其中 `bool` 也没有通过 C 的 `<stdbool.h>` 提供。

## 影响

- C11 项目无法直接包含该套件目录中的头文件。
- 依赖 C ABI 的调用方无法编译或链接到该接口。
- 头文件目录和实际可用语言不一致，增加集成成本。

## 触发条件

1. C 项目包含 `dhcp_c_api.h` 或其依赖的 `dhcp_result_event.h`。
2. 使用 C 编译器编译该源文件。

## 修复建议

为 C 调用方提供只含 C 类型的声明：使用指针参数替代 C++ 引用，移除默认参数，并在 C 分支包含 `<stdbool.h>`。如需保留 C++ 便利接口，应放入独立的 C++ 头文件。
