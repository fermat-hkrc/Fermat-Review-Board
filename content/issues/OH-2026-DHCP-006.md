## 问题概述

`interfaces/kits/c` 下的公开 DHCP 头文件以 C API 目录和 C 风格函数声明的形式提供，但普通 C11 翻译单元无法包含 `dhcp_c_api.h`。其包含链中使用了未通过 `<stdbool.h>` 声明的 `bool`，而 `dhcp_c_api.h` 自身还使用了 C++ 引用参数和默认参数。

这不是链接阶段或平台适配问题：只要 C 调用方写一个仅包含该头文件的源文件，编译器便在解析公开声明时停止。对于需要使用 C 编译器的 native 调用方，接口当前不可用。

## 受影响声明

| 文件与位置 | 当前声明 | 为什么 C11 不可解析 |
| --- | --- | --- |
| `dhcp_result_event.h:61` | `bool isOptSuc;` | 未包含 `<stdbool.h>`，C 中没有内建 `bool` 类型名 |
| `dhcp_c_api.h:48` | `StartDhcpClient(const RouterConfig &config)` | `&` 为 C++ 引用语法 |
| `dhcp_c_api.h:56` | `DealWifiDhcpCache(..., const IpCacheInfo &ipCacheInfo)` | `&` 为 C++ 引用语法 |
| `dhcp_c_api.h:65` | `StopDhcpClient(..., bool bIpv4 = true)` | C 既没有默认参数，也可能未声明 `bool` |

相关生产声明如下：

```cpp
DhcpErrorCode StartDhcpClient(const RouterConfig &config);
DhcpErrorCode DealWifiDhcpCache(int32_t cmd, const IpCacheInfo &ipCacheInfo);
DhcpErrorCode StopDhcpClient(const char *ifname, bool bIpv6, bool bIpv4 = true);
```

## 正常调用路径与触发链

```text
C 项目源文件
  │ #include "dhcp_c_api.h"
  ▼
dhcp_c_api.h
  │ 包含 dhcp_result_event.h
  │ 解析 bool 字段 → C11 找不到类型名
  │ 继续解析公开函数 → 遇到 & 和 = true
  ▼
C 编译器在声明阶段报错，业务代码尚未开始编译
```

### 最小触发条件

1. 调用方使用 C 编译器，而非 C++ 编译器。
2. 源文件包含 `interfaces/kits/c/dhcp_c_api.h`。
3. 使用标准 C11 语法检查或正常构建。

验证文件仅包含该公开头文件，并使用 `clang -std=c11 -Wall -Werror -fsyntax-only`。实际诊断包括 `unknown type name 'bool'` 和两个 `expected ')'`，没有引入业务实现、替身或额外输入。

## 影响分析

### 直接行为

- C 调用方不能编译通过公开 DHCP API。
- 接口的目录、命名和声明方式与其实际支持的语言不一致。
- 集成者必须改用 C++、自行改写声明或放弃该接口。

### 用户与集成影响

- 纯 C 的 native 组件无法按公开路径接入 DHCP 服务。
- 构建系统在包含头文件时即失败，无法进入功能测试阶段。
- 将 C++ 特性意外传入 C ABI 头文件会增加跨语言封装与维护成本。

### 边界

本条确认的是 C 语言兼容性。使用 C++ 编译器时这些 C++ 声明可能可解析，因此不能把该问题描述为所有 C++ 调用方均无法使用 API。

## 修复建议

为 C 和 C++ 分别暴露符合各自语言规则的声明。C ABI 层应只使用 C 类型和指针参数：

```c
#ifdef __cplusplus
extern "C" {
#else
#include <stdbool.h>
#endif

DhcpErrorCode StartDhcpClient(const RouterConfig *config);
DhcpErrorCode DealWifiDhcpCache(int32_t cmd, const IpCacheInfo *ipCacheInfo);
DhcpErrorCode StopDhcpClient(const char *ifname, bool bIpv6, bool bIpv4);
```

如需保留引用和默认参数，应将它们作为 C++ 包装接口放在独立的 C++ 头文件中，而不是混入 `interfaces/kits/c`。

## 回归测试建议

| 用例 | 编译语言 | 期望 |
| --- | --- | --- |
| 仅包含 `dhcp_c_api.h` | C11 | 语法检查通过 |
| 调用三个受影响 API | C11 | 参数以指针与显式布尔值传递，编译通过 |
| 既有 C++ 调用 | C++17 | 保持 ABI/行为兼容或通过包装层兼容 |
| C/C++ 混合项目 | 分别编译 C 与 C++ 单元 | 两种语言均不依赖未定义类型或语言特性 |
