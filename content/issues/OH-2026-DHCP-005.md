## 问题概述

`IpInRange` 对网络字节序的 IPv4 整数直接使用大小比较。在小端系统上，内存表示的数值顺序与 IPv4 地址的自然顺序不同，导致同一网段中的合法地址被错误判定为不在范围内。

## 根本原因

地址和边界均以网络字节序保存，但代码直接比较：

```cpp
if (ip >= beginIp && ip <= endIp) {
    return DHCP_TRUE;
}
```

等值比较仍然有效，但顺序比较应在转换为主机字节序后进行。

## 影响

- DHCP 地址池中的可分配地址可能被错误排除。
- 一段连续的正常配置范围会出现部分地址无法使用的情况。
- 地址池利用率和分配结果会随处理器字节序而变化。

## 触发条件

1. DHCP 服务端运行在小端系统。
2. 配置的范围跨越 IPv4 地址低位字节的排序边界。
3. 对范围内地址调用 `IpInRange`。

例如在 `192.168.1.250` 到 `192.168.2.10` 的 `/16` 范围内，`192.168.2.1` 会被当前比较逻辑拒绝。

## 修复建议

在进行范围大小比较前，对 `ip`、`beginIp` 和 `endIp` 使用 `ntohl` 转为主机字节序；网络地址和掩码相关计算保持使用其既有字节序约定。
