## 问题概述

`IpInRange` 先使用已有网络地址函数确认候选地址、起点和终点处于同一网段，随后直接对 `uint32_t` 值做 `>=` 和 `<=` 比较。这些值来自 IPv4 网络字节序表示；在常见的小端处理器上，它们作为本地整数参与大小比较时的顺序并不等同于点分十进制 IPv4 地址顺序。

结果是，文本意义上位于配置范围内的地址可能在最后一步被拒绝。问题会影响跨越低位字节排序边界的地址池范围，而不是仅限于无效地址输入。

## 根本原因

生产函数的网络一致性检查与范围检查使用了不同的字节序假设：

```cpp
int IpInRange(uint32_t ip, uint32_t beginIp, uint32_t endIp, uint32_t netmask)
{
    uint32_t network = NetworkAddress(ip, netmask);
    uint32_t firstNet = NetworkAddress(beginIp, netmask);
    uint32_t secondNet = NetworkAddress(endIp, netmask);
    if (network != firstNet || firstNet != secondNet) {
        return 0;
    }
    if (ip >= beginIp && ip <= endIp) {  // 直接比较网络序整数
        return DHCP_TRUE;
    }
    return DHCP_FALSE;
}
```

`ParseIpAddr` 和相关地址函数保留网络表示以便网络计算和传输，这是合理的；问题仅在需要“数值区间顺序”时没有先转换为同一主机序。等值比较不受影响，跨地址边界的大小比较则受影响。

## 正常调用路径与触发链

```text
DHCP Server 读取或计算地址池范围
  │ beginIp / endIp 为网络序 IPv4 地址
  ▼
需要判断某个候选地址是否属于该范围
  ▼
IpInRange(candidate, beginIp, endIp, netmask)
  │ NetworkAddress 确认三者处在同一网段
  │ 对 network-order uint32_t 做原始 >= / <=
  ▼
小端设备上，合法候选地址被返回为 DHCP_FALSE
```

### 可复现输入

| 参数 | 值 |
| --- | --- |
| 起点 | `192.168.1.250` |
| 终点 | `192.168.2.10` |
| 掩码 | `255.255.0.0` (`/16`) |
| 候选地址 | `192.168.2.1` |

四个地址处于同一 `/16`，且候选地址的点分十进制值在起点与终点之间。真实 `ParseIpAddr` 和真实 `IpInRange` 在小端验证环境返回 `0`。

## 影响分析

### 直接行为

- 某些合法地址池成员被判定为范围外。
- 地址分配、保留地址检查或相关配置校验可能跳过可用地址。
- 结果取决于范围边界与处理器字节序，而不是纯粹的 IPv4 语义。

### 用户可见后果

- DHCP 服务配置了连续地址池，但部分客户端无法获得预期地址。
- 可用地址没有耗尽时，服务仍可能表现为“无合适地址”或给出不一致分配结果。
- 同一配置在不同架构上可能表现不同，增加部署与排障难度。

### 边界

起点、终点、候选地址不在同一网段时，函数会在前置检查处返回 false，这是正确行为。本条只针对已经通过同网段检查、却因原始网络序大小比较被错误拒绝的范围成员。

## 修复建议

将参与范围顺序比较的三个值转换为主机字节序，网络地址计算仍沿用现有约定：

```cpp
const uint32_t hostIp = ntohl(ip);
const uint32_t hostBegin = ntohl(beginIp);
const uint32_t hostEnd = ntohl(endIp);
if (hostIp >= hostBegin && hostIp <= hostEnd) {
    return DHCP_TRUE;
}
```

应同时复查 `IpInNetwork` 等以原始 `uint32_t` 进行范围比较的辅助函数，确保它们使用相同的顺序规则。

## 回归测试建议

| 用例 | 期望 |
| --- | --- |
| 单 `/24` 内的中间地址 | 正确接受 |
| `/16` 中跨 `/24` 边界的地址 | 正确接受 |
| 起点与终点本身 | 均正确接受 |
| 同网段但小于起点、或大于终点 | 正确拒绝 |
| 不同网段地址 | 保持拒绝 |
| 小端和大端构建 | 返回结果一致 |
