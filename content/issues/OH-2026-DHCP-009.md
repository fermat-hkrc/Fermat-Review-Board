## 问题概述

DHCP Server 在处理已有租约的 REQUEST 时，会把 Host Name option 写入 AddressBinding::deviceName。

GetHostNameOption 仅复制本次 option 的实际长度，不清空已有数组，也不写新的字符串结束符。当同一租约原先有较长名称、后来更新为较短名称时，旧名称尾部继续保留。

例如先写入 long-name，后写入 x，最终保存和读取到的是 xong-name，而不是 x。

## 源码中的直接原因

当前实现只做长度上限检查和按长度复制：

    if (optHostName->length >= DEVICE_NAME_STRING_LENGTH) {
        return REPLY_NONE;
    }
    if (memcpy_s(bindin->deviceName, DEVICE_NAME_STRING_LENGTH,
        (char*)optHostName->data, optHostName->length) != EOK) {
        return REPLY_NONE;
    }

长度检查保证本次复制不超出数组，但不会改变本次长度之后的旧字节。对于短名称，旧的结束符也不会移动到新名称之后。

## 正常调用路径

    同一客户端已有 DHCP lease
      -> 后续 DHCP REQUEST 携带较短 Host Name option
      -> OnReceivedRequest 找到已有 lease
      -> ParseDhcpOption(received, lease)
      -> GetHostNameOption(received, lease)
      -> 只覆盖 deviceName 的前 N 个字节
      -> 读取到新前缀加旧后缀

这条路径使用已有租约和合法短名称更新，不要求超长名称或不完整报文。

## 最新主线验证

本条在 GitCode master 的 f52429ee1873c13c8ed55bde0cb9914b2dfedc43 上重新构建生产 dhcp_s_server.cpp 与 dhcp_option.cpp。

同一个 AddressBinding 依次接收：

    Host Name = long-name
    Host Name = x

生产函数输出：

    hostname_after_short_update='xong-name' expected='x'

## 影响

- 租约元数据不再反映最新主机名。
- 管理界面、日志和设备列表可能显示新前缀与旧后缀拼接后的名称。
- 用户修改设备名称后，网络侧记录可能继续显示错误名称。

首次写入、等长更新和更长更新不一定表现出该结果；本条针对同一缓冲区的长名称到短名称更新。

## 修复建议

复制前清空整个数组，或复制后明确设置结束符：

    if (memset_s(bindin->deviceName, DEVICE_NAME_STRING_LENGTH, 0,
        DEVICE_NAME_STRING_LENGTH) != EOK) {
        return REPLY_NONE;
    }
    if (memcpy_s(bindin->deviceName, DEVICE_NAME_STRING_LENGTH,
        optHostName->data, optHostName->length) != EOK) {
        return REPLY_NONE;
    }
    bindin->deviceName[optHostName->length] = '\0';

现有长度检查必须保留，确保结束符索引在数组范围内。
