## 问题概述

DHCP Server 在处理已有租约的 REQUEST 时会调用 `ParseDhcpOption`，再由 `GetHostNameOption` 将 option 12（Host Name）写入租约的 `AddressBinding::deviceName`。该函数只复制 option 的实际长度，不在复制前清空目标缓冲区，也不在复制后写入终止符。

当同一租约先拥有较长主机名、随后收到较短的有效主机名时，旧内容的尾部会继续留在 `deviceName`。例如第一次为 `long-name`、第二次为 `x`，之后读取到的字符串是 `xong-name`，而不是最新的 `x`。

## 受影响路径

| 位置 | 作用 |
| --- | --- |
| `dhcp_s_server.cpp:1235-1255` | 查找 Host Name option 并复制到 `binding->deviceName` |
| `dhcp_s_server.cpp:1338-1351` | `ParseDhcpOption` 对绑定租约调用 `GetHostNameOption` |
| `dhcp_s_server.cpp:1370-1400` | `OnReceivedRequest` 从地址池取得已有 lease 后调用 `ParseDhcpOption` |

关键复制逻辑：

```cpp
if (optHostName->length >= DEVICE_NAME_STRING_LENGTH) {
    return REPLY_NONE;
}
if (memcpy_s(bindin->deviceName, DEVICE_NAME_STRING_LENGTH,
    (char*)optHostName->data, optHostName->length) != EOK) {
    return REPLY_NONE;
}
```

长度上限检查只保证本次复制不会超出数组，不能清除旧字节。`memcpy_s` 复制的长度正好等于 option 长度，因此它也不会自动为较短更新追加字符串终止符。

## 正常调用路径与触发链

```text
同一客户端先获得或更新一个 DHCP lease
  │ Host Name option = "long-name"
  ▼
AddressBinding::deviceName 保存 "long-name\0"
  │
同一客户端后续发送正常 DHCPREQUEST
  │ Host Name option = "x"
  ▼
OnReceivedRequest
  │ GetLease(...) 找到已有 lease
  │ ParseDhcpOption(received, lease)
  │ GetHostNameOption 仅复制 1 个字节
  ▼
deviceName 字节变为 "xong-name\0"
```

### 最小触发条件

1. 服务端对同一客户端或同一 lease 保存了已有 `AddressBinding`。
2. 先前 Host Name 比本次 Host Name 长。
3. 后续正常 DHCP REQUEST 带有较短、且长度小于 `DEVICE_NAME_STRING_LENGTH` 的 Host Name option。
4. 任何组件读取、显示、记录或依据 `deviceName` 进行处理。

验证通过真实 `GetHostNameOption` 对同一个 `AddressBinding` 先写入 `long-name`，再写入 `x`。实际输出为 `hostname_after_short_update='xong-name' expected='x'`。选项查找和生产复制函数均未被替换。

## 影响分析

### 直接行为

- 租约元数据不再反映最新 Host Name。
- 对于缩短更新，名称会混合新前缀和旧后缀。
- 日志、客户端列表和读取该字段的组件可能使用过期标识。

### 用户可见后果

- DHCP 管理界面显示错误的设备名称。
- 基于主机名的识别、展示或审计记录可能将设备与旧名称混淆。
- 用户正常修改设备主机名后，网络侧仍显示拼接后的旧名称。

### 边界

首次写入、等长更新或更长更新通常会覆盖更多字节，因此不一定表现为旧后缀。本条针对同一缓冲区发生的较短有效更新，不涉及超长输入绕过。

## 修复建议

在复制前清空整个目标缓冲区，或在复制后明确写入终止符：

```cpp
if (memset_s(bindin->deviceName, DEVICE_NAME_STRING_LENGTH, 0,
    DEVICE_NAME_STRING_LENGTH) != EOK) {
    return REPLY_NONE;
}
if (memcpy_s(bindin->deviceName, DEVICE_NAME_STRING_LENGTH,
    optHostName->data, optHostName->length) != EOK) {
    return REPLY_NONE;
}
bindin->deviceName[optHostName->length] = '\0';
```

保留现有长度检查，确保终止符位置始终处于数组范围内。

## 回归测试建议

| 用例 | 期望 |
| --- | --- |
| 首次写入 Host Name | 内容与 option 完全相同 |
| 长名称更新为短名称 | 缓冲区只包含新名称和终止符 |
| 短名称更新为长名称 | 内容与新 option 完全相同 |
| 空或缺失 Host Name option | 保持项目定义的现有行为 |
| 接近上限的名称 | 不越界，终止符正确 |
| 正常 `OnReceivedRequest` 路径 | 更新已有 lease 后读取名称正确 |
