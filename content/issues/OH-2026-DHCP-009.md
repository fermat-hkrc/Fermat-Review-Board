## 问题概述

DHCP 服务端在已有租约上更新较短的 Host Name 选项时，只覆盖新字符串的长度，不清空尾部也不写入终止符。旧主机名的剩余字符会保留在租约元数据中。

## 根本原因

`GetHostNameOption` 仅复制选项中实际长度的字节：

```cpp
if (memcpy_s(bindin->deviceName, DEVICE_NAME_STRING_LENGTH,
    (char*)optHostName->data, optHostName->length) != EOK) {
    return REPLY_NONE;
}
```

函数没有在复制前清空 `deviceName`，也没有在复制后设置 `deviceName[optHostName->length]`。正常 REQUEST 路径会对已有 `lease` 调用 `ParseDhcpOption`，因此同一租约会复用旧缓冲区内容。

## 影响

- 租约记录、日志或读取该字段的组件会看到过期的主机名后缀。
- 设备标识与最新 DHCP Host Name 选项不一致。
- 基于主机名进行展示或管理的流程可能关联到错误名称。

## 触发条件

1. 同一租约先收到较长的 Host Name，例如 `long-name`。
2. 该租约后续收到更短的 Host Name，例如 `x`。
3. 服务端在已有租约上处理 DHCP REQUEST。

当前实现会保留为 `xong-name`，而不是 `x`。

## 修复建议

复制前清空 `deviceName`，并在复制后显式写入终止符。应保持长度上限检查，并为同一租约的长名称到短名称更新增加回归测试。
