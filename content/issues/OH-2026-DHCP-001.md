## 问题概述

`DhcpClientCallBack::OnIpSuccessChanged` 在栈上创建未初始化的 C 结构体 `DhcpResult`。后续复制 DNS 和地址信息时，代码直接递增其中的 `dnsNumber` 和 `addrNumber`，最终把不可预测的计数传给应用回调。

## 根本原因

局部结构体没有进行零初始化：

```cpp
DhcpResult dhcpResult;
dhcpResult.iptype = result.iptype;
// 只设置部分字段
ResultInfoCopy(dhcpResult, result);
```

复制函数把未初始化值当作有效计数：

```cpp
dhcpResult.dnsList.dnsNumber++;

if (dhcpResult.addrList.addrNumber >= DHCP_ADDR_MAX_NUMBER) {
    break;
}
```

## 影响

- 应用收到的 DNS 数量和地址数量可能远大于实际值。
- 正常 DHCP 成功事件可能携带损坏的结果元数据。
- 依赖计数遍历结果的调用方可能读取无效条目或拒绝本次网络配置。

## 触发条件

1. DHCP 客户端正常取得地址。
2. 结果中包含至少一个 DNS 地址或 IPv6 地址条目。
3. `OnIpSuccessChanged` 将结果转换为公开 C 回调结构。
4. 未初始化计数被递增并传给已注册的应用回调。

## 修复建议

创建结构体时进行值初始化，并在复制前显式设置两个计数为 0：

```cpp
DhcpResult dhcpResult {};
```

同文件的 `OnDhcpOfferReport` 使用相同声明方式，也应一并检查。
