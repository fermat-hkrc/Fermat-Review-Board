## 问题概述

`DhcpClientCallBack::OnIpSuccessChanged` 将内部 C++ `OHOS::DHCP::DhcpResult` 转换为公开回调使用的 C 结构体 `::DhcpResult`。该函数在栈上声明 `DhcpResult dhcpResult;`，但没有进行值初始化。随后 `ResultInfoCopyExt` 把 `dnsList.dnsNumber` 和 `addrList.addrNumber` 当作已从 0 开始的计数器使用。

当 DHCP 正常获取地址并携带 DNS 或地址列表时，回调会收到未定义初值加上实际元素数的计数。计数既可能远大于实际数组长度，也可能已经超过上限，导致复制提前跳过。问题出现在正常成功通知路径，不需要无效 DHCP 报文。

## 受影响函数与字段

| 位置 | 作用 | 未初始化字段的后续用途 |
| --- | --- | --- |
| `frameworks/native/src/dhcp_event.cpp:71-98` | `ResultInfoCopyExt` | 递增 `dnsList.dnsNumber`；以 `addrList.addrNumber` 作为数组下标和上限判断 |
| `frameworks/native/src/dhcp_event.cpp:100-122` | `OnIpSuccessChanged` | 声明未初始化 `DhcpResult`，并将其传给已注册应用回调 |

## 根本原因

入口只为部分标量字段赋值，未初始化嵌套计数器：

```cpp
// frameworks/native/src/dhcp_event.cpp
DhcpResult dhcpResult;
dhcpResult.iptype = result.iptype;
dhcpResult.isOptSuc = result.isOptSuc;
dhcpResult.uOptLeasetime = result.uLeaseTime;
// ...
ResultInfoCopy(dhcpResult, result);
```

随后复制函数把未初始化值当作现有记录数：

```cpp
if (strncpy_s(dhcpResult.dnsList.dnsAddr[i], DHCP_DNS_DATA_MAX_LEN,
    result.vectorDnsAddr[i].c_str(), result.vectorDnsAddr[i].length()) == EOK) {
    dhcpResult.dnsList.dnsNumber++;
}

for (const auto &addrItem : result.IpAddrMap) {
    if (dhcpResult.addrList.addrNumber >= DHCP_ADDR_MAX_NUMBER) {
        break;
    }
    // addrNumber 同时作为数组下标
    dhcpResult.addrList.addrNumber++;
}
```

即使 DNS 数组的元素按 `i` 写入，导出的 `dnsNumber` 也不是实际写入个数；IPv6 地址路径则还会使用未初始化的 `addrNumber` 进行边界判断和索引。

## 正常调用路径与触发链

```text
DHCP 客户端取得租约、DNS 或 IPv6 地址
  │
  ▼
DhcpClientCallBack::OnIpSuccessChanged(status, ifname, internalResult)
  │ 声明 DhcpResult dhcpResult;（未置零）
  ▼
ResultInfoCopy / ResultInfoCopyExt
  │ dnsNumber++ / 使用 addrNumber 作为下标
  ▼
mapClientCallBack[ifname]->OnIpSuccessChanged(..., &dhcpResult)
  ▼
应用读取 DNS/地址数量，并按该元数据处理网络结果
```

### 最小触发条件

1. 应用已为接口注册 `ClientCallBack::OnIpSuccessChanged`。
2. DHCP 客户端正常完成地址配置，进入 `OnIpSuccessChanged`。
3. 结果至少包含一个 DNS 条目或一个地址条目。
4. 应用读取回调结构中的 `dnsList.dnsNumber` 或 `addrList.addrNumber`。

验证在真实回调实现中提供一个 DNS 地址。为了使未初始化状态可复现，测试只在编译时使用固定自动变量填充值；生产回调代码、复制函数和公开回调入口均未改写。回调实际得到 `dnsCount=2863311531`，而输入仅有一个 DNS 条目。

## 影响分析

### 直接行为

- DNS 数量可能与实际 DNS 条目数不一致。
- IPv6 地址计数可能在复制前已被视为达到上限，导致有效地址未被复制。
- 回调消费者若按错误计数遍历数组，可能读取未写入的数组槽位或拒绝当前网络结果。

### 用户可见后果

- 网络配置已经成功，但上层显示的 DNS 或地址数量异常。
- 依赖回调结果保存、展示或二次处理网络参数的组件可能认为数据无效。
- 同一输入在不同构建或调用时可能得到不同计数，造成难以复现的网络初始化问题。

### 边界

本条确认的是未初始化字段进入真实公开回调的行为。未宣称所有调用环境都会出现同一个数值；具体值由栈内容决定。固定填充值验证的是“字段未被初始化且会被公开使用”，不是运行时自然值的唯一表现。

## 修复建议

在声明处进行值初始化，并把计数器初始化保持在数据构造边界：

```cpp
DhcpResult dhcpResult {};
dhcpResult.iptype = result.iptype;
// 其余赋值保持不变
```

如结构体设计允许，也可在 `ResultInfoCopyExt` 开始处显式设置 `dnsNumber` 和 `addrNumber` 为 0，但不能仅依赖调用者。应同时检查同文件中其他以 `DhcpResult` 作为局部输出对象的成功回调路径。

## 回归测试建议

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 单 DNS 成功回调 | 一个 DNS 地址 | `dnsNumber == 1` |
| 多 DNS 成功回调 | N 个有效 DNS，N 不超过上限 | `dnsNumber == N` |
| 地址列表成功回调 | 一个或多个 IPv6 地址 | `addrNumber` 从 0 开始递增，数组索引连续 |
| 空列表成功回调 | 无 DNS、无地址 | 两个计数均为 0 |
