## 漏洞概述

`FileCopyLocalListener` 的通知线程使用 `eventFd_` 和 `notifyFd_` 执行 `poll`、读取和循环判断。`StopListener` 与析构路径会并发关闭并重置相同描述符，现有 `readMutex_` 没有覆盖描述符从取得到完成使用的整个生命周期。

## 根本原因

**位置**：`frameworks/native/distributed_file_inner/src/copy/file_copy_listener.cpp`

```cpp
pollfd fds[] = {{eventFd_, POLLIN, 0}, {notifyFd_, POLLIN, 0}};
while (eventFd_ >= 0 && notifyFd_ >= 0) {
    poll(fds, 2, -1);
    // 继续读取成员描述符
}

void FileCopyLocalListener::StopListener()
{
    CloseNotifyFd(); // 另一线程关闭并重置相同描述符
}
```

析构路径还会先关闭描述符再等待线程结束，使通知线程能够观察到无效或已经复用的 descriptor number。

## 影响

- 通知线程可能操作已经关闭的描述符。
- 文件复制进度通知可能提前终止、遗漏或返回错误码。
- 描述符数字被系统快速复用时，存在误操作其他资源的生命周期风险。

## 触发条件

本进程取消或销毁仍在运行的文件复制监听器，同时通知线程正在 `poll` 或读取 inotify 数据。

## 修复建议

使用明确的停止事件唤醒通知线程，在线程退出并 join 后再关闭成员描述符。若必须并发关闭，应在同一锁下取得和失效描述符，并确保线程只使用受生命周期保护的本地副本。
