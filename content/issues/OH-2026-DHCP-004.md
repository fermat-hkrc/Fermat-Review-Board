## 问题概述

DHCP 客户端保存缓存时，即使 `fwrite` 只写入部分内容，或 `fflush`、`fsync` 失败，函数仍返回成功并清空内存中的全部缓存记录。

## 根本原因

`SaveConfig` 只记录短写日志，没有把失败传递给调用方；随后无条件忽略刷新和同步的返回值，并清空 `m_allIpCached`：

```cpp
if (ret != static_cast<uint32_t>(content.length())) {
    DHCP_LOGE("... fwrite() failed!");
}
(void)fflush(fp);
(void)fsync(fileno(fp));
(void)fclose(fp);
m_allIpCached.clear();
return 0;
```

`fopen(..., "w")` 已在写入前截断旧文件，因此后续短写会留下空文件或不完整文件。

## 影响

- 写入异常时，持久化缓存可能为空或不完整。
- 本轮内存缓存也会被清空，调用方无法根据返回值保留或重试原数据。
- 后续 DHCP 缓存读取可能缺少原本可用的地址信息。

## 触发条件

1. 客户端存在待保存的 DHCP 缓存记录。
2. 目标存储介质在写入、刷新或同步阶段出现异常，例如空间不足或 I/O 异常。
3. 调用 `DhcpResultStoreManager::SaveConfig`。

## 修复建议

检查 `fwrite`、`fflush`、`fsync` 和 `fclose` 的返回值。只有在内容完整且已成功写入后才清空内存缓存；失败时应返回错误并保留原记录。
