## 问题概述

`DhcpResultStoreManager::SaveConfig` 把 DHCP 缓存序列化后直接以 `"w"` 打开目标文件。只要 `fopen` 成功，后续的 `fwrite` 短写、`fflush` 失败、`fsync` 失败和 `fclose` 失败都不会改变函数返回值。函数还会无条件清空 `m_allIpCached`，最后返回 0。

因此，存储介质在写入阶段发生正常的 I/O 异常时，旧文件已经被截断，新的内存缓存也已被丢弃，但上层仍得到“保存成功”。这会把一次可重试的持久化失败变成缓存数据丢失。

## 受影响路径

| 步骤 | 当前代码行为 | 问题 |
| --- | --- | --- |
| 打开文件 | `fopen(m_fileName.c_str(), "w")` | 成功打开即截断旧内容 |
| 写入 | `fwrite` 的返回值只写日志 | 短写不向调用者报告 |
| 刷新与同步 | `(void)fflush`、`(void)fsync`、`(void)fclose` | 三个失败结果均被忽略 |
| 清理 | `m_allIpCached.clear()` | 即使写入失败也删除唯一内存副本 |
| 返回 | `return 0` | 调用者无法重试或保留数据 |

## 根本原因

生产代码将写入结果与清理顺序拆开处理：

```cpp
uint32_t ret = fwrite(content.c_str(), 1, content.length(), fp);
if (ret != static_cast<uint32_t>(content.length())) {
    DHCP_LOGE("Save config file: %{public}s, fwrite() failed!", m_fileName.c_str());
}
(void)fflush(fp);
(void)fsync(fileno(fp));
(void)fclose(fp);
m_allIpCached.clear();
std::vector<IpInfoCached>().swap(m_allIpCached);
return 0;
```

错误日志没有控制流效果。尤其是 `"w"` 模式会在内容写完之前截断旧文件，短写后不仅新内容不完整，原本可恢复的历史缓存也已经不存在。

## 正常调用路径与触发链

```text
DHCP 客户端有待保存的缓存记录
  │
  ▼
DhcpResultStoreManager::SaveConfig()
  │ fopen(path, "w")：旧文件被截断
  │ 生成配置文本
  │ fwrite(...)：存储介质短写或失败
  │ 仅记录日志，继续执行
  │ 忽略 fflush/fsync/fclose 的返回值
  │ 清空 m_allIpCached
  ▼
向调用方返回 0，磁盘和内存缓存均不完整或为空
```

### 最小触发条件

1. 缓存管理器内至少有一条待保存的 DHCP 记录。
2. 目标路径可打开，但在写入、刷新、同步或关闭阶段失败。
3. 调用 `SaveConfig`。

这类条件可由空间耗尽、文件系统 I/O 错误、可移除存储异常或底层写入中断产生。验证只在 `fwrite` 系统边界模拟短写，真实序列化、错误路径和缓存清理均使用生产实现；结果是 `save_result=0` 且缓存条目数变为 0。

## 影响分析

### 直接行为

- 磁盘文件可能为空、截断或只含部分记录。
- 内存中的完整缓存被清空。
- 调用方无法依据返回值判断是否应重试保存。

### 用户可见后果

- 后续启动或网络恢复时，组件不能读取原本可用的 DHCP 缓存。
- 用户可能经历重新获取地址、网络状态恢复变慢或缓存配置消失。
- 日志虽有写入失败记录，但业务层已收到成功值，自动恢复逻辑不会触发。

### 边界

本条不依赖路径校验绕过，也不改变缓存格式。问题只在 `fopen` 已成功后、持久化没有完整完成的错误处理路径中出现。

## 修复建议

仅在全部写入并成功关闭后才释放内存缓存。最小处理应检查每个步骤：

```cpp
const size_t written = fwrite(content.data(), 1, content.size(), fp);
const bool writeOk = written == content.size();
const bool flushOk = writeOk && fflush(fp) == 0;
const bool syncOk = flushOk && fsync(fileno(fp)) == 0;
const bool closeOk = fclose(fp) == 0;
if (!writeOk || !flushOk || !syncOk || !closeOk) {
    return DHCP_E_FAILED;
}
m_allIpCached.clear();
return DHCP_E_SUCCESS;
```

更稳妥的做法是写入同目录临时文件、同步后原子替换目标文件，以避免 `"w"` 在失败前破坏旧缓存。

## 回归测试建议

| 用例 | 注入点 | 期望 |
| --- | --- | --- |
| 正常保存 | 无注入 | 返回成功，文件完整，内存缓存按设计清理 |
| 短写 | `fwrite` 返回小于内容长度 | 返回失败，内存缓存保留 |
| 刷新失败 | `fflush` 返回错误 | 返回失败，内存缓存保留 |
| 同步失败 | `fsync` 返回错误 | 返回失败，内存缓存保留 |
| 关闭失败 | `fclose` 返回错误 | 返回失败，避免报告成功 |
| 替换失败 | 临时文件重命名失败 | 旧缓存文件仍可读，调用方得到失败 |
