## 问题概述

Lite 客户端调用 `StartDhcpClient` 时，proxy 未写入服务端处理函数预期的 `SvcIdentity`。服务端因此返回失败结果，但 proxy 只检查 IPC 传输状态和 `exception`，未检查 reply 中的 `retCode`，最终向调用方返回成功。

## 根本原因

proxy 写入接口令牌、异常整数和配置字段：

```cpp
(void)WriteInt32(&req, 0);
(void)WriteString(&req, config.ifname.c_str());
```

请求分派已经读取该异常整数，随后 `OnStartDhcpClient` 仍试图读取 `SvcIdentity`：

```cpp
SvcIdentity sid;
bool readSid = ReadRemoteObject(req, &sid);
```

该读取失败后，服务端将失败码写入 reply。proxy 只检查 `owner.exception`，没有检查 `owner.retCode`：

```cpp
if (owner.exception) {
    return DHCP_E_FAILED;
}
return DHCP_E_SUCCESS;
```

## 影响

- Lite 调用方收到成功结果，但 DHCP 客户端实际没有启动。
- 上层流程无法依据返回值发起重试或显示失败状态。
- 设备网络初始化可能停留在未启动状态。

## 触发条件

1. Lite 平台完成 DHCP 客户端服务注册。
2. 调用 `DhcpClientProxy::StartDhcpClient`。
3. IPC 传输本身返回成功，但服务端处理函数因缺少 `SvcIdentity` 返回失败。

## 修复建议

统一 proxy 和 stub 的请求字段定义：如果启动操作不需要回调对象，删除 stub 中的 `ReadRemoteObject`；否则由 proxy 写入匹配的 `SvcIdentity`。同时让 proxy 检查并返回 `owner.retCode`。
