## 漏洞概述

`wpa_work.c` 中的 `CheckSsid` 函数在向全局数组 `g_useSsid[]` 写入时对计数器 `g_useSsidCount` 无上限检查。反复调用可使计数器超出数组大小，造成全局数据段越界写入。

## 根本原因

**位置**: `services/bundlemgr_lite/bundle_daemon/sample/wpa_work.c:244`

```c
#define MAX_SSID_COUNT 10

static char g_useSsid[MAX_SSID_COUNT][MAX_SSID_LEN];
static int g_useSsidCount = 0;

int CheckSsid(const char *ssid)
{
    // 检查是否已存在
    for (int i = 0; i < g_useSsidCount; i++) {
        if (strcmp(g_useSsid[i], ssid) == 0) {
            return 1;  // 已存在
        }
    }
    // 添加新 SSID — 无边界检查
    strcpy(g_useSsid[g_useSsidCount], ssid);  // OOB if g_useSsidCount >= MAX_SSID_COUNT
    g_useSsidCount++;  // 无上限检查
    return 0;
}
```

**问题**:
1. `g_useSsidCount` 递增无上限检查
2. 当 `g_useSsidCount >= MAX_SSID_COUNT` 时，`g_useSsid[g_useSsidCount]` 越界
3. `strcpy` 向越界地址写入，覆写全局数据段相邻变量
4. 无重复检查失败时的短路返回

## 影响

- 全局数据段越界写入
- 覆写相邻全局变量可能改变程序行为
- 若 SSID 内容可控，可写入任意数据到预测位置
- Wi-Fi 功能异常或进程崩溃

## 触发条件

1. 连接超过 10 个不同的 Wi-Fi SSID
2. 每次连接新 SSID 时调用 `CheckSsid`
3. 第 11 次及之后的调用越界写入 `g_useSsid[10]` 及之后位置
4. 若 SSID 为攻击者控制的接入点名称，可写入任意内容

## 修复建议

```c
int CheckSsid(const char *ssid)
{
    for (int i = 0; i < g_useSsidCount; i++) {
        if (strcmp(g_useSsid[i], ssid) == 0) {
            return 1;
        }
    }
+   if (g_useSsidCount >= MAX_SSID_COUNT) {
+       return -1;  // 数组已满
+   }
    strcpy(g_useSsid[g_useSsidCount], ssid);
    g_useSsidCount++;
    return 0;
}
```
