## 漏洞概述

`DataBuffer` 的拷贝构造函数分配 `other.size_ + 1` 字节并拷贝 `other.size_` 字节数据，但不写入 null 终止符。`Peek()` 方法返回 `(char*)data_`，调用者通过 `printf("%s", buf.Peek())` 等方式读取时，会越界读取堆内存。

同时，构造函数 `DataBuffer(int size)` 不验证 `size > 0`，传入负数时 `new uint8_t[size+1]` 分配 0 字节，然后 `data_[size]` 越界写入。

## 问题代码

**拷贝构造函数缺少 null 终止符**：

```cpp
// data_buffer.cpp:44-53
DataBuffer::DataBuffer(const DataBuffer &other) noexcept
{
    if (other.data_ && other.size_) {
        capacity_ = other.size_;
        data_ = new uint8_t[capacity_ + 1];        // 分配 size+1 字节
        auto ret = memcpy_s(data_, capacity_ + 1, other.data_, other.size_);
        if (ret != EOK) {
            size_ = other.size_;                    // 错误处理：只设 size，没清 data
        }
        size_ = other.size_;
        // 缺少: data_[size_] = '\0';               ← 没有 null 终止符
    }
}
```

**构造函数不验证负数 size**：

```cpp
// data_buffer.cpp:32-38
DataBuffer::DataBuffer(int size)
{
    data_ = new uint8_t[size + 1];   // size=-1 → new uint8_t[0]
    data_[size] = '\0';              // data_[-1] = '\0' ← OOB write
    capacity_ = size;                // capacity = -1
    size_ = 0;
}
```

## 触发条件

1. 创建 DataBuffer 并写入数据
2. 使用拷贝构造函数创建副本
3. 通过 `Peek()` 读取副本内容（返回 `char*`）
4. 任何字符串操作（printf、strlen、strcmp 等）越界读取

触发路径：

```
DataBuffer buf1(100);
buf1.PushData("Hello OHOS", 10);
DataBuffer buf2(buf1);                     // 拷贝构造：分配 11 字节，拷贝 10 字节，无 null 终止
printf("%s", buf2.Peek());                 // printf 读取越界 → ASan: heap-buffer-overflow
```

## 影响

- **堆越界读取**：拷贝构造后的 DataBuffer 的 `Peek()` 返回的字符串没有 null 终止符
- **信息泄露**：越界读取可能泄露堆上其他数据
- **构造函数负数 size**：未验证参数范围，可能导致 OOB 写入
- **影响范围**：DataBuffer 是 castengine_wifi_display 的基础缓冲区类，被 RTP/RTSP 协议解析、网络传输等广泛使用

## 修复建议

```diff
 DataBuffer::DataBuffer(const DataBuffer &other) noexcept
 {
     if (other.data_ && other.size_) {
         capacity_ = other.size_;
         data_ = new uint8_t[capacity_ + 1];
         auto ret = memcpy_s(data_, capacity_ + 1, other.data_, other.size_);
-        if (ret != EOK) {
-            size_ = other.size_;
-        }
+        if (ret == EOK) {
+            data_[other.size_] = '\0';  // 添加 null 终止符
+        }
         size_ = other.size_;
     }
 }

 DataBuffer::DataBuffer(int size)
 {
+    if (size <= 0) {
+        data_ = nullptr;
+        capacity_ = 0;
+        size_ = 0;
+        return;
+    }
     data_ = new uint8_t[size + 1];
     data_[size] = '\0';
```

### 1. 验证方法：GN Target-Compile (C++)

### 4. 漏洞触发详情

ASan 报告显示：

- 分配的缓冲区：11 字节（`other.size_ + 1`，其中 `other.size_ = 10`）
- 越界读取位置：`0 bytes after 11-byte region` — 从缓冲区末尾开始
- 触发点：`printf` 内部的 `printf_common` 函数读取字符串时越界
- 根本原因：`memcpy_s` 拷贝了 10 字节数据到 11 字节缓冲区，第 11 字节未初始化（不是 '\0'）
