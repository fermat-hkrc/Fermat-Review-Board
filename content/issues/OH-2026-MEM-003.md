## 漏洞概述

`RtpHeader::GetCsrcData()` 返回 `&payload_`（偏移量 12），但不检查缓冲区是否有足够空间容纳 CC 字段声称的 CSRC 数据。`GetPayloadData()` 和 `GetExtData()` 同样基于 `&payload_` 加偏移量返回指针，无边界验证。

当接收到 CC=15 的 RTP 包但包长度仅 12 字节时，`GetCsrcData()` 返回指向分配末尾之后的指针。调用者读取该指针导致堆越界读取。

## 问题代码

**GetCsrcData 无边界检查**：

```cpp
// rtp_packet.cpp:29-36
uint8_t *RtpHeader::GetCsrcData()
{
    if (!csrc_) {
        return nullptr;
    }
    return &payload_;  // 返回 offset 12，不检查 rtp_size >= 12 + GetCsrcSize()
}
```

**GetPayloadData 无边界检查**：

```cpp
// rtp_packet.cpp:79-82
uint8_t *RtpHeader::GetPayloadData(size_t rtp_size)
{
    return &payload_ + GetPayloadOffset(rtp_size);  // 偏移量未验证
}
```

**GetExtData 无边界检查**：

```cpp
// rtp_packet.cpp:64-72
uint8_t *RtpHeader::GetExtData(size_t rtp_size)
{
    if (!ext_) {
        return nullptr;
    }
    auto ext_ptr = &payload_ + GetCsrcSize();  // 未验证 GetCsrcSize() 是否在范围内
    return ext_ptr + 4;
}
```

## 触发条件

1. 接收到网络 RTP 包（如通过 WiFi Display 协议栈）
2. CC 字段非零（攻击者控制）
3. 包实际长度小于 12 + CC*4 字节
4. 调用 `GetCsrcData()`、`GetExtData()` 或 `GetPayloadData()` 读取数据

触发路径：

```
接收 RTP 包 → RtpPacket::PushData(data, len)
→ DataBuffer 分配恰好 len 字节
→ RtpPacket::GetHeader() 返回 (RtpHeader*)data_
→ GetCsrcData() 返回 &payload_ (offset 12)
→ CC=15 声称 60 字节 CSRC，但包仅 12 字节
→ 读取 offset 12+ → heap-buffer-overflow
```

## 影响

- **堆越界读取**：攻击者通过构造 RTP 包头控制读取偏移和长度
- **信息泄露**：越界读取可泄露堆上其他数据（相邻分配的内存内容）
- **后续崩溃**：`GetPayloadData()` 返回的指针被解引用可能导致段错误
- **影响范围**：RTP 是 WiFi Display 协议栈核心，`RtpPacket` 在所有媒体传输路径使用

### 漏洞触发

Verification 2：构造 CC=15 的 12 字节 RTP 包（无 CSRC 数据），通过 `GetCsrcData()` 触发 OOB：

```
PushData: 12 bytes, Size()=12, Capacity()=12
CC=15 claims 60 bytes CSRC (but 0 bytes available)
Data() = 0x502000000030, GetCsrcData() = 0x50200000003c (offset 12)
```

ASan 输出：

```
==3858332==ERROR: AddressSanitizer: heap-buffer-overflow on address 0x50200000003c at pc 0x5c059e5d7ef5
READ of size 1 at 0x50200000003c thread T0
    #0 0x5c059e5d7ef4 in main ../../test/rtp_poc.cpp:99

0x50200000003c is located 0 bytes after 12-byte region [0x502000000030,0x50200000003c)
allocated by thread T0 here:
    #0 in operator new[](unsigned long, std::nothrow_t const&)
    #1 in OHOS::Sharing::DataBuffer::PushData(char const*, int) data_buffer.cpp:139

SUMMARY: AddressSanitizer: heap-buffer-overflow ../../test/rtp_poc.cpp:99 in main
```

ASan 确认：12 字节缓冲区（DataBuffer::PushData 精确分配 12 字节），读取 offset 12（0 bytes after region）触发 heap-buffer-overflow。

### 技术细节

1. **分配精确性**：DataBuffer::PushData 在容量不足时 `new uint8_t[size_ + dataLen]`，对于初始 12 字节推送恰好分配 12 字节。无多余空间。
2. **OOB 指针来源**：GetCsrcData() 返回 `&payload_`，即 `RtpHeader*` 偏移 12 处。由于 RtpHeader 是 `__attribute__((packed))`，`payload_` 位于精确偏移 12。
3. **ASan shadow 验证**：shadow byte `04` 表示 8 字节组中仅前 4 字节可访问（bytes 8-11），byte 12 已被 poison。

## 修复建议

```diff
 uint8_t *RtpHeader::GetCsrcData()
 {
     if (!csrc_) {
         return nullptr;
     }
+    if (GetCsrcSize() > rtp_size - RTP_HEADER_SIZE) {
+        return nullptr;
+    }
     return &payload_;
 }
```

所有返回 `&payload_ + offset` 的方法都需要类似的边界检查。
