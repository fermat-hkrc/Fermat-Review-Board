## 问题概述

标准版本 DHCP Server 回调存在两类协议问题。`OnServerSuccess` 的 proxy 与 stub 使用不同字段顺序；`OnServerLeasesChanged` 和 `OnServerSerExitChanged` 则在 proxy 中直接返回，没有发送 IPC 请求。

## 根本原因

`OnServerSuccess` 的发送端在异常字段之后依次写入接口名和设备数量：

```cpp
data.WriteInt32(0);
data.WriteString(ifname);
data.WriteInt32(stationInfos.size());
```

公共分发函数读取异常字段后，接收端却先读取设备数量，再读取接口名：

```cpp
int size = data.ReadInt32();
std::string ifName = data.ReadString();
```

另外两个回调没有任何序列化或 `SendRequest`：

```cpp
void DhcpServerCallbackProxy::OnServerLeasesChanged(...)
{
    return;
}

void DhcpServerCallbackProxy::OnServerSerExitChanged(...)
{
    return;
}
```

## 影响

- 设备上线回调中的接口名和设备数量被错误解析。
- 租约变化事件无法送达注册回调。
- DHCP Server 退出事件无法送达注册回调。
- 管理界面或上层服务可能显示错误的客户端列表和服务状态。

## 触发条件

1. 调用方正常注册 DHCP Server 回调。
2. 服务端上报设备上线、租约变化或服务退出事件。
3. 回调通过标准 IPC proxy 传输到应用侧 stub。

## 修复建议

统一 `OnServerSuccess` 两端的序列化顺序。建议接收端先读取 `ifName`，再读取 `size`。同时为租约变化和服务退出回调实现完整的字段写入、请求发送和异常处理。
