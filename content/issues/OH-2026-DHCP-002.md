## 问题概述

DHCP Server 向已注册回调发送设备上线信息时，发送端和接收端对同一 IPC 消息使用了不同字段顺序。

发送端在公共异常字段之后依次写入接口名、站点数量和每个站点的信息。接收端却先读取整数数量，再读取接口名。这样一来，接收端把接口名的序列化数据当作数量，后续读取位置也随之偏移。

本条只覆盖 OnServerSuccess 的字段顺序问题。没有把其他未完成的回调方法纳入本条结论。

## 源码中的字段顺序

服务端业务路径会在取得当前站点列表后调用回调：

    DhcpServerServiceImpl::DeviceInfoCallBack
      -> OnServerSuccess(ifname, stationInfos)

发送端的实际顺序：

    data.WriteInt32(0);
    data.WriteString(ifname);
    data.WriteInt32(stationInfos.size());
    for (auto stationInfo: stationInfos) {
        data.WriteString(stationInfo.deviceName);
        data.WriteString(stationInfo.macAddr);
        data.WriteString(stationInfo.ipAddr);
    }

公共分发函数已经先读取上面的异常字段。随后接收端使用的顺序却是：

    int size = data.ReadInt32();
    std::string ifName = data.ReadString();

两处顺序直接相反，不需要依赖额外配置判断。

| 消息位置 | 发送端 | 接收端 | 结果 |
| ---: | --- | --- | --- |
| 1 | interface token | 公共分发逻辑读取 | 一致 |
| 2 | 异常字段 0 | 公共分发逻辑读取 | 一致 |
| 3 | 接口名字符串 | 读取为 size | 错位 |
| 4 | 站点数量 | 读取为 ifName | 错位 |
| 5 | 站点字段 | 按错误 size 继续读取 | 后续继续偏移 |

## 正常调用路径

    DHCP Server 已注册回调
      -> 服务端生成站点列表
      -> DeviceInfoCallBack(ifname)
      -> DhcpServerCallbackProxy::OnServerSuccess
      -> IPC 消息发送
      -> DhcpServreCallBackStub::RemoteOnServerSuccess
      -> 上层回调收到偏移后的接口名和站点列表

最小条件是已注册标准 DHCP Server 回调，并发生一次设备信息通知。输入不需要修改 IPC 原始字节，也不需要模拟非正常系统状态。

## 最新主线验证

本条在 GitCode master 的 f52429ee1873c13c8ed55bde0cb9914b2dfedc43 上重新构建。

验证链接真实的生产 proxy 与生产 stub，只提供 in-process IPC 边界和记录回调结果的对象。输入为接口名 wlan0 和一个站点。

    success_callback=1 ifname='' station_count=6 expected_ifname='wlan0' expected_count=1

成功回调确实到达，但接口名为空，站点数量为 6，而不是发送端提供的 1。具体的错误数量来自字符串 framing；本条的判定只依赖它不等于原始站点数量。

## 影响

- 使用回调显示已连接设备时，接口名和设备数量不可靠。
- 接收端可能按错误数量读取后续字段，得到不完整或错误的站点数据。
- DHCP Server 本身已经取得正确站点信息，但该信息无法按原始语义交付给回调订阅者。

## 修复建议

保持单一字段协议。接收端应先读取接口名，再读取数量：

    std::string ifName = data.ReadString();
    int size = data.ReadInt32();
    if (size < 0 || size > MAXIMUM_SIZE) {
        reply.WriteInt32(0);
        return DHCP_E_SUCCESS;
    }

建议将 proxy 与 stub 的字段顺序放在同一份接口测试中维护。

## 回归测试建议

| 输入 | 期望 |
| --- | --- |
| wlan0，0 个站点 | 回调获得 wlan0 和空列表 |
| wlan0，1 个站点 | 回调获得 wlan0 和完全相同的 1 个站点 |
| wlan0，多个站点 | 数量和每个字段均与发送端一致 |
