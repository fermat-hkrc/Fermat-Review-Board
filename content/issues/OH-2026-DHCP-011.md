## 问题概述

客户端检测到地址冲突后会进入 `Declining` 状态并发送 DHCPDECLINE。`DhcpDecline` 将 Requested IP Address 和 Server Identifier 各追加两次，生成包含重复选项的报文。

## 根本原因

同一对选项连续写入两次：

```cpp
AddOptValueToOpts(packet.options, REQUESTED_IP_ADDRESS_OPTION, clientIp);
AddOptValueToOpts(packet.options, SERVER_IDENTIFIER_OPTION, serverIp);
AddOptValueToOpts(packet.options, REQUESTED_IP_ADDRESS_OPTION, clientIp);
AddOptValueToOpts(packet.options, SERVER_IDENTIFIER_OPTION, serverIp);
```

## 影响

- DHCPDECLINE 报文比预期包含额外的重复选项。
- 不同服务端对重复选项的处理可能不同，降低互操作性。
- 报文解析和日志中的选项数量与调用方预期不一致。

## 触发条件

1. DHCP 客户端已取得候选地址。
2. 地址冲突检测进入 `Declining`。
3. 客户端调用 `DhcpDecline` 发送 DHCPDECLINE 报文。

## 修复建议

删除第二次 Requested IP Address 和 Server Identifier 写入，并增加对 DHCPDECLINE 选项数量及顺序的报文回归测试。
