## 问题概述

DHCP 客户端检测到 IPv4 地址冲突后进入 `Declining` 状态，并调用 `DhcpDecline` 发送 DHCPDECLINE。该函数已经将 Requested IP Address（option 50）和 Server Identifier（option 54）各写入一次，却在紧接着的两行再次写入完全相同的两项。

生成的 DHCPDECLINE 报文因此包含两个 option 50 和两个 option 54。客户端的状态机、报文初始化和发送路径均可正常运行，但最终在线路上的 option 集合不符合这个函数本身的一次性字段语义，服务端对重复 option 的容忍方式可能不同。

## 受影响路径

| 位置 | 作用 |
| --- | --- |
| `dhcp_client_state_machine.cpp:770-800` | `Declining` 在冲突次数阈值前调用 `DhcpDecline` |
| `dhcp_client_state_machine.cpp:1733-1759` | 构造 DHCPDECLINE 并追加 DHCP option |
| `dhcp_options.cpp` | 追加 option 的底层实现，由生产代码链接使用 |

重复写入位于同一函数的连续路径：

```cpp
AddClientIdToOpts(&packet);
AddOptValueToOpts(packet.options, REQUESTED_IP_ADDRESS_OPTION, clientIp);
AddOptValueToOpts(packet.options, SERVER_IDENTIFIER_OPTION, serverIp);
AddOptValueToOpts(packet.options, REQUESTED_IP_ADDRESS_OPTION, clientIp); // 重复
AddOptValueToOpts(packet.options, SERVER_IDENTIFIER_OPTION, serverIp);    // 重复
```

## 正常调用路径与触发链

```text
客户端发现候选 IPv4 地址冲突
  │
  ▼
DhcpClientStateMachine::Declining(timestamp)
  │ conflictCount 未超过最大次数
  │ DhcpDecline(transId, requestedIp, serverIp)
  ▼
DhcpDecline
  │ 初始化 DHCP_DECLINE 数据包
  │ 写入 Client Identifier
  │ 两次写入 option 50 和 option 54
  ▼
SendToDhcpPacket
  ▼
服务端收到包含重复 Requested IP / Server Identifier 的 DHCPDECLINE
```

### 最小触发条件

1. DHCP 客户端已进入地址冲突处理，而非超过最大冲突次数后的终止路径。
2. `m_requestedIp4` 与 `m_serverIp4` 已设置。
3. 调用 `Declining` 或直接进入 `DhcpDecline` 的正常状态机路径。

验证构造真实状态机所需的接口和地址上下文，调用生产 `DhcpDecline`，并仅在发送边界观察最终数据包。捕获结果为 `requested_ip_options=2 server_id_options=2 expected_each=1`；生产状态机和 option 写入函数未被重写。

## 影响分析

### 直接行为

- DHCPDECLINE 报文携带重复且值相同的两个关键 option。
- 报文长度比必要值更大。
- 服务端或中间设备需要自行选择如何处理重复 option。

### 用户可见后果

- 某些 DHCP 服务端可能接受其中一个 option，另一些可能拒绝或记录异常报文。
- 地址冲突恢复流程在不同网络设备上表现不一致。
- 协议调试与日志会看到与调用方意图不一致的重复字段。

### 边界

本条只针对地址冲突触发的 DHCPDECLINE。它不表示普通 DISCOVER、REQUEST、RELEASE 报文也会重复写入这两个 option。

## 修复建议

删除第二次的两项追加，保持单一的明确 option 序列：

```cpp
AddClientIdToOpts(&packet);
AddOptValueToOpts(packet.options, REQUESTED_IP_ADDRESS_OPTION, clientIp);
AddOptValueToOpts(packet.options, SERVER_IDENTIFIER_OPTION, serverIp);
```

建议在发送前的测试中解析 options 而非只比较报文长度，以便同时验证出现次数、顺序和值。

## 回归测试建议

| 用例 | 期望 |
| --- | --- |
| 地址冲突进入 `Declining` | `DhcpDecline` 被调用，状态转为 INIT 的既有行为保持 |
| 捕获 DHCPDECLINE | option 50 恰好 1 个，值为请求地址 |
| 捕获 DHCPDECLINE | option 54 恰好 1 个，值为服务端地址 |
| Client Identifier | 仍按原逻辑出现 |
| 重复 option 输入检查 | 解析器或测试明确拒绝本函数再次添加同码字段 |
