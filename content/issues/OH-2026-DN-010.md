## 漏洞概述

`OnNotifyDelayedNotification` 在日志参数中无锁读取 `triggerNotificationList_.size()`，而插入、删除和查找路径使用 `triggerNotificationMutex_` 修改同一个 list。地理围栏或 timer 回调可能来自主服务队列之外的执行上下文，因此无锁读取与修改能够并发。

## 根本原因

**位置**：`services/ans/src/advanced_notification_geofence_service.cpp`

```cpp
ANS_LOGD("trigger list size=%{public}zu", triggerNotificationList_.size());
// 随后的业务查找才进入 triggerNotificationMutex_ 保护的函数
```

日志求值本身会读取容器内部状态。即使结果不参与业务逻辑，它仍必须与修改方使用同一同步机制。

## 影响

- 日志可能记录错误或不一致的列表数量。
- 无锁 `std::list::size()` 与并发修改构成 C++ 数据竞争。
- 实际业务查找仍使用锁，因此当前影响主要限于诊断信息和低概率运行异常。

## 触发条件

地理围栏延时通知回调在读取 size 时，另一个 timer 或服务任务正在插入或删除 `triggerNotificationList_`。

## 修复建议

在 `triggerNotificationMutex_` 下取得 size 快照后再记录日志，或删除这条非必要日志。不得在锁外直接读取容器状态。
